# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

| Java | `java` | **(b) 끊긴 링크이자 자리 예약.** `java-in-finance` 가 "언어 자체는 여기"라며 넘겼고, **`Java` 라는 alias 를 일부러 비워 뒀다** — 그 문서가 alias 를 가져가면 이 문서가 영영 관계 화면에 못 걸린다. **(a) 수요 2위**(공고 1,655건 · 22.1% · 동반 Spring 44.5%)라 `market` 이 채워질 문서다. 축은 **JVM 이 만든 성질** — 하위 호환성, GC 와 힙 튜닝, 한 번 정한 LTS 를 오래 끌고 가는 이유, Kotlin 이 같은 런타임에서 무엇을 바꿨나 | Oracle Java SE 지원 로드맵(LTS 표), JEP·JLS, Spring 공식 문서. 금융 쪽 맥락은 이미 `java-in-finance` 에 있으니 **거기와 겹치지 않게 언어·런타임만** 쓴다 |
| STM32 | `stm32` | **(b) 끊긴 링크 — 두 문서가 가리킨다**(`atmega128` 의 "다음 자리", `gpio-register` 의 가운데 열). **미룸에서 올라왔다** — 조건이었던 `gpio-register` 를 끝냈으므로 이제 비교할 자리가 있다. **(c) 공고 근거가 두껍다**: `마이크로컨트롤러(STM32, AVR 등)`, `MCU (AVR, ESP32, STM32 등)` 처럼 세 칩이 한 줄에 묶여 나온다. 축은 **AVR 에 없던 것들** — 클럭 트리와 RCC(왜 클럭부터 켜야 하나), 시리즈 파편화(F1 의 CRL/CRH vs F4 의 MODER), HAL/LL/CubeMX 의 층, NVIC | ST 레퍼런스 매뉴얼(RM0008·RM0090은 이미 `gpio-register` 에서 인용했다), ST 의 HAL 문서. **`gpio-register` 와 겹치지 않게** GPIO 는 링크로 넘기고 클럭·인터럽트 컨트롤러·툴체인 쪽을 쓴다 |
| SPI | `spi` | **(b) 끊긴 링크.** `i2c` 의 비교표가 가운데 열을 통째로 비워 뒀다("속도가 필요할 때 가는 곳"). **(c) 공고에서 I²C·UART 와 늘 한 줄에 묶여 나온다** — `시리얼 통신 프로토콜(UART, SPI, I2C) 구현 경험` 류가 모집중 다수. 축은 **I²C 가 못 하는 것을 어떻게 하는가** — CS 로 고르는 방식(주소가 없다), 전이중, 클럭 모드(CPOL/CPHA)라는 악명 높은 함정, 데이지 체인. `i2c` 문서가 이미 비교표와 '선을 줄이는 비용' 틀을 세워 뒀으므로 **그 틀을 그대로 뒤집어 쓰면 된다** | 부품 데이터시트의 SPI 타이밍도(모드 0~3), MCU 레퍼런스 매뉴얼의 SPI 절. ⚠️ SPI 는 **단일 규격 문서가 없다**(모토로라 관행에서 굳어졌다) — 그 사실 자체를 문서에 적어야 한다. 1차 자료는 벤더 문서뿐 |
| 멱등성 | `idempotency` | **(c) 회의에서 그냥 쓰이는 말.** 결제·주문 공고의 자격요건에 `멱등성`이 설명 없이 등장한다. 재시도·중복 요청·네트워크 타임아웃과 한 몸이라 백엔드 면접의 단골이기도 하다. 정의는 한 줄인데 *언제 멱등키를 쓰고 언제 분산 락을 쓰나*를 가른 글은 드물다 | HTTP 메서드 정의(RFC 9110), Stripe·Toss 결제 API 의 idempotency key 문서, 국내 커머스 기술블로그의 재시도 글 |
| Modbus | `modbus` | **(b) 끊긴 링크.** `rs485` 가 "주소와 프레임을 주는 위층"이라며 가리킨다. **(c) 공고 근거가 RS-485 보다 두껍다** — 모집중 공고에서 `Modbus` 72건 vs `RS-485` 30건(합집합 83건). `RS-485(Modbus) 및 CAN 통신 드라이버 개발`(원익피앤이)처럼 **괄호로 묶여 나오는데 둘의 층이 다르다는 설명이 어디에도 없다.** 축은 RTU 와 TCP 의 갈림, 레지스터 4종(코일·이산입력·입력·홀딩)이라는 낡은 모델이 왜 아직 표준인가, 주소 1-based/0-based 혼란 | modbus.org 의 `Modbus over Serial Line V1.02`(rs485 문서가 이미 받아 인용했다)와 `MODBUS Application Protocol V1.1b3`. 둘 다 공개 PDF 라 링크 가능한 1차 자료다 |
| RTOS | `rtos` | **(b) 끊긴 링크.** `interrupt` 가 "ISR 을 짧게 유지한 다음 그 일을 어디로 넘기나"의 답으로 가리킨다. **(c) 공고 문장이 있다** — `제한된 자원 환경에서의 태스크 스케줄링, 인터럽트 처리, 결정적 타이밍 확보`(디하이브). 축은 **인터럽트만으로 안 되는 지점** — 우선순위 역전, 태스크 간 통신(큐·세마포어), ISR 에서 부를 수 있는 API(`…FromISR`), 스택을 태스크마다 따로 갖는 대가 | FreeRTOS 공식 문서(커널 API 레퍼런스와 우선순위 역전 설명이 공개돼 있다), Zephyr 문서. ⚠️ 실시간성 정의는 벤더마다 다르니 "경성/연성"을 단정하기 전에 1차 자료 확인 |
| DMA | `dma` | **(b) 끊긴 링크.** `interrupt` 가 "바이트마다 인터럽트를 걸면 지는 싸움"의 반대편으로 가리킨다. `uart` 의 오버런 절에서 시작해 `interrupt` 의 링 버퍼로 이어진 줄기의 종착점이다. 축은 **CPU 를 안 거치고 옮긴다는 것의 대가** — 캐시 일관성, 버퍼 정렬, 전송 완료를 결국 인터럽트로 안다는 순환 | ATmega128 에는 DMA 가 없다 — 그래서 **STM32 레퍼런스 매뉴얼(RM0090 등, 이미 `gpio-register` 가 인용 중)** 이 1차 자료가 된다. `stm32` 문서와 겹치지 않게 클럭·HAL 은 그쪽으로 넘긴다 |
| multiprocessing | `multiprocessing` | **(b) 끊긴 링크 — 두 문서가 가리킨다**(`gil` 이 "GIL 을 피하는 정식 경로", `asyncio` 가 "CPU 바운드는 저쪽"). **(c) 3.14 에서 POSIX 기본 시작 방식이 `fork`→`forkserver` 로 바뀌었는데**(gil 문서가 확인한 사실) 그 변화가 무엇을 깨는지 설명한 한국어 글이 드물다. 축은 시작 방식 3종(fork/spawn/forkserver)이 만드는 서로 다른 함정 | multiprocessing 공식 문서의 "Contexts and start methods" 절, 3.14 릴리스 노트. 실습은 `gil` 문서의 워커 확장 곡선 drill 을 그대로 이어 쓴다 |
| FastAPI | `fastapi` | **(b) 끊긴 링크 — `asyncio` 가 "`def` 와 `async def` 를 다르게 처리하는 실제 사례"로 가리킨다.** **(a) 수요가 크다** — `tech_relations.json` 에서 Python 동반 기술 9위(484건 · Python 공고의 15.8%). 축은 **프레임워크가 대신 해 주는 것과 그래서 숨는 것** — 의존성 주입, Pydantic 검증이 런타임 비용인 지점, `def` 핸들러가 스레드풀로 넘어가는 동작(그 풀 크기가 문서에 없다는 점도) | FastAPI 공식 문서(`/async/` 절은 `asyncio` 문서가 이미 대조했다), Starlette·Uvicorn 문서, Pydantic v2 문서 |
| 워치독 | `watchdog` | **(b) 끊긴 링크.** `interrupt` 가 "ISR 안에서 멈춰 버렸을 때 누가 깨우나"로 가리킨다. **(c) 설명이 없는 말이다** — 펌웨어 공고의 `안정성`·`무인 운전` 같은 문장이 실제로 요구하는 장치인데 이름이 잘 안 나온다. 축은 **리셋이 해결책이 되는 상황과 그것이 은폐가 되는 상황**, 그리고 왜 인터럽트로 먹이면 안 되는가 | ATmega128 데이터시트의 WDT 절(WDTCR·WDCE 시퀀스, `interrupt` 문서가 이미 PDF 본문 추출에 성공했다), STM32 의 IWDG/WWDG |
