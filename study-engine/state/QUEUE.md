# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

|---|---|---|---|



| OpenAPI (API 명세) | `openapi` | **`contract-testing` 이 끊긴 링크로 남긴 자리**이고 **`vs-spec` 표가 한쪽을 비워 둔 채 끝났다** — 예시 기반(Pact)의 반대편인 **명세 기반**. ⭐ **국내 수요는 오히려 이쪽이 압도적으로 크다: 234건(모집중 82)** (`계약 테스트` 는 8건). (a)수요 + (b)끊긴 링크가 동시에 성립하는 드문 경우다. 근거: 데일리펀딩 `API 문서화(Swagger/OpenAPI), 시스템 아키텍처 문서 작성 능력`, ⭐ 지로 `**Swagger 기반 API 계약**으로 프론트엔드 코드 생성까지 잇는 개발 경험 구축`(계약이라는 낱말을 그쪽에서 쓴다), 밀레니얼웍스·큐픽스 `OpenAPI Generator`, 젤리 `백엔드 개발자와 API 스펙, 에러 코드, 데이터 구조, 예외 상황 등을 협의`. ⚠️ **`오픈 API`(공공데이터 개방)와 헷갈린다** — 의심 4건으로 적지만 국내 문맥에서 흔한 충돌이니 문장을 읽고 거른다. 축: ①**문서인가 계약인가**(사람이 읽는 것 vs 코드가 읽는 것 — 이 갈림이 문서 전체를 정한다) ②⭐**코드 생성**(명세에서 클라이언트·서버 스텁이 나온다 = 명세가 진실이 되는 순간 → `grpc` 의 IDL 과 같은 자리) ③**명세가 코드와 어긋나는 문제**(주석에서 뽑기 vs 명세 먼저 쓰기 — spec-first vs code-first) ④**무엇을 표현 못 하나**(순서·상태 전이·비즈니스 규칙 → `contract-testing` 이 메우는 자리) ⑤**버전과 폐기**(공개 API 에서 계약 테스트를 못 쓸 때 이것이 유일한 수단 → `data-contract` 의 호환성) | ⭐ **1차 자료** — **OpenAPI Specification 원문(spec.openapis.org)** 이 공개 HTML 표준 문서이고 **필수/선택 필드와 버전별 차이(3.0 vs 3.1 의 JSON Schema 정합)** 가 명시돼 있다. **Swagger/OpenAPI Generator 문서**는 코드 생성 쪽. ⚠️ **`grpc` 와 겹치지 않게 — 그쪽은 이미 IDL·필드 번호를 다뤘으니 여기는 'HTTP API 를 사후에 기술하는 것'의 어려움**(gRPC 는 정의가 먼저인데 REST 는 대개 코드가 먼저다) |
| 암호화와 키 관리 | `encryption` | **`dlp` 가 끊긴 링크로 남긴 자리** — 데이터를 덜 위험하게 만드는 **세 번째 방법**(비식별·마스킹 다음). 그리고 **`secrets` 가 '시크릿을 어디에 두나'까지만 다루고 '무엇으로 잠그나'를 안 다뤘다.** ⭐ **수요가 아주 크다: 381건(모집중 147)** — (a)수요 + (b)끊긴 링크가 함께 성립한다. 근거: 메디트 `보안·인증 체계 (OAuth2.0, JWT, TLS, IAM Policy, **KMS** 등) 구축 및 검증`, 넥스트증권 `저장소 분리, **KMS 키 분리**, 네트워크 경계, 접근통제 및 감사로그 체계를 설계합니다`, 왓섭 `민감정보 암호화, 로그 마스킹`, 의식주컴퍼니 `RDS 암호화`, 루닛 `모델 IP 보호(암호화된 모델 배포/복호화)`. ⭐⭐ **국내 고유의 각이 있다** — 포밸류소프트 `암호화(AES·**SEED·ARIA**)`. **SEED·ARIA 는 국산 표준 알고리즘**이고 공공·금융 요건에서 요구된다. **해외 자료가 절대 다루지 않는 자리**라 이 백과사전이 쓸 이유가 분명하다. ⚠️ `암호화폐`·`블록체인 지갑` 은 다른 얘기이니 문장을 읽고 거른다(셈에서 이미 제외). 축: ①**전송 중 vs 저장 시**(무엇을 막고 무엇을 못 막나 — 저장 암호화는 디스크 도난만 막는다) ②⭐**키를 어디에 두나가 전부다**(데이터 옆에 키를 두면 암호화하지 않은 것과 같다 → `secrets`) ③**봉투 암호화**(데이터 키를 마스터 키로 감싼다 — KMS 가 파는 구조) ④**키 교체**(rotate 를 안 해서가 아니라 **교체하면 옛 데이터를 못 읽어서** 안 한다) ⑤**국내 요건**(SEED·ARIA, 그리고 무엇이 암호화 대상인지) | ⭐ **1차 자료** — **AWS KMS 문서의 봉투 암호화(envelope encryption)와 키 교체(automatic key rotation) 페이지**가 **'왜 이 구조인가'를 스스로 설명하는 자리**이고(이 엔진에서 여섯 번 통한 형태), **Google Cloud KMS** 도 후보. SEED·ARIA 는 **KISA/TTA 표준 문서**를 찾되 ⚠️ **유료·PDF 이면 `network-separation`·`ohms-law` 처리**(공개 요약·기관 페이지로 대신하고 밝힌다). ⚠️ **`secrets` 와 겹치지 않게 — 시크릿 보관은 그쪽, 여기는 데이터 암호화** |
