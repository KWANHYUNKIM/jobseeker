# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

## 대기

| 낱말 | slug | 왜 이 낱말 | 무엇을 읽을 수 있나 |
|---|---|---|---|
| UART | `uart` | **(b) 끊긴 링크.** `atmega128` 의 UART 절이 "본체는 따로"라고 미뤄 뒀다. **(c) 공고에는 `Socket 통신`·`시리얼 통신`이 그냥 쓰인다.** 보율·시작/정지 비트·패리티·오차 계산(±2% 벽)·11.0592MHz 크리스탈의 이유가 한 문서에 들어간다. 펌웨어 디버깅의 8할이 여기서 나온다 | 데이터시트의 USART 절(UBRR 공식·오차표), RS-232/TTL 레벨 차이, 리눅스 `termios` 문서 |
| Python | `python` | **(a) 수요 1위.** `tech_relations.json` 기준 **공고 2,648건 · 전체의 35.4%** 로 이 데이터셋에서 가장 많이 요구되는 기술이다. 다만 "파이썬 문법"을 또 쓰는 것은 이 엔진의 일이 아니다. 축은 **선택**이어야 한다 — 언제 `list` 대신 `deque`, 언제 `dict` 대신 `dataclass`, 언제 스레드 대신 프로세스(GIL), 언제 `asyncio`. `when_to_use` 가 문서의 절반을 차지하는 첫 사례가 될 것 | `tech_relations` 의 동반 기술(AWS 36.0% · Docker 24.5% · K8s 23.9%)이 **문서의 뼈대를 정해 준다** — 파이썬이 실무에서 도는 자리가 '컨테이너에 올린 데이터·모델 서빙'이라는 뜻이다. 1차 자료는 PEP·CPython 문서·`collections` 레퍼런스 |
| 금융권은 왜 Java 인가 | `java-in-finance` | **(c) 설명이 없는 말.** Java 는 공고 **1,655건(22.1%)** 으로 2위이고 Spring 과 44.5% 함께 나온다. 그런데 *왜 금융권이 유독 Java 인가*는 아무도 안 쓴다 — 전자금융감독규정·망분리·JVM 의 오랜 하위 호환·SI 인력 시장·기존 코어뱅킹 자산이 얽힌 **도메인 상식**이다. 브리핑 엔진의 포밸류소프트 건(NH농협 차수, `망분리`·`전문(Flat File)`)이 같은 벽을 만났다 | 전자금융감독규정 원문, 금융보안원 가이드, 각 은행 기술블로그(차세대 시스템 전환기), 공고 원문의 `망분리`·`전문` 문장 |
| GPIO 레지스터 | `gpio-register` | **(b) 끊긴 링크.** `atmega128` 의 DDR/PORT/PIN 을 **칩에 매이지 않은 개념**으로 올리는 문서. STM32 의 MODER/ODR/IDR, ESP32 의 GPIO 매트릭스가 같은 자리에서 어떻게 다른 이름을 갖는지 나란히 놓으면, AVR 에서 배운 것이 다음 칩으로 옮겨지는 다리가 된다 | 각 칩 레퍼런스 매뉴얼의 GPIO 절. 표 하나로 세 칩을 비교하는 `compare` 테이블이 이 문서의 알맹이 |
| I²C | `i2c` | **(b) 끊긴 링크 — 두 문서가 가리킨다** (`atmega128` 의 TWI 절, `pull-up-resistor` 의 계산식 절). 그리고 **(c) 공고 근거가 이 엔진에서 가장 두껍다** — `SPI, I2C, CAN, UART 등 하드웨어 인터페이스` 류 문장이 모집중 공고에 반복해서 박혀 있다(메디인테크·디하이브·크래블·웰리시스·니어스랩·BNSR). 풀업 문서가 계산식까지 깔아 뒀으므로, 여기서는 주소·ACK·클럭 스트레칭·버스 점유 같은 프로토콜 쪽을 쓴다 | NXP UM10204 원문(1차 자료), ATmega128 데이터시트의 TWI 절, 공고 원문 여러 건 |
| 옴의 법칙 | `ohms-law` | **(b) 끊긴 링크.** `pull-up-resistor` 가 "이 문서의 모든 숫자가 나오는 한 줄"이라며 가리킨다. `atmega128` 의 첫 실습(LED 전류 제한 저항 계산)도 같은 식이다. **가장 작은 낱말이지만 이 계열 문서 전부의 바닥**이라 한 번은 따로 써 둬야 다른 문서에서 반복하지 않는다 | 계산식 자체는 1차 자료가 필요 없다. 대신 **전력(P=VI)과 저항의 정격 와트**, E24 계열처럼 '계산값과 실제로 살 수 있는 값이 다른' 지점을 실무 쪽에서 받친다 |
| 멱등성 | `idempotency` | **(c) 회의에서 그냥 쓰이는 말.** 결제·주문 공고의 자격요건에 `멱등성`이 설명 없이 등장한다. 재시도·중복 요청·네트워크 타임아웃과 한 몸이라 백엔드 면접의 단골이기도 하다. 정의는 한 줄인데 *언제 멱등키를 쓰고 언제 분산 락을 쓰나*를 가른 글은 드물다 | HTTP 메서드 정의(RFC 9110), Stripe·Toss 결제 API 의 idempotency key 문서, 국내 커머스 기술블로그의 재시도 글 |

## 미룸

| 낱말 | 왜 미뤘나 | 언제 다시 볼까 |
|---|---|---|
| STM32 | `atmega128` 이 "다음 자리"로 가리키고 수요도 크지만, **`gpio-register` 를 먼저 써야 비교할 자리가 생긴다.** 지금 쓰면 또 하나의 칩 소개가 된다 | `gpio-register` 를 끝낸 뒤 |
| 인터럽트 | 큰 낱말이라 **폴링·타이머·컨텍스트·재진입**까지 한 문서에 들어간다. `uart` 를 쓰고 나면 "수신을 인터럽트로 받는다"는 실제 사례가 생겨 훨씬 쉽게 써진다 | `uart` 다음 |
| Kubernetes | 공고 1,183건(15.8%)으로 수요는 크지만, **이 엔진의 값은 '설명이 없는 말'에서 나온다.** 쿠버네티스는 한국어 자료가 이미 두껍다. 쓰더라도 `when_to_use`(언제 안 쓰나)만 남기는 형태가 맞다 | 큐가 비고 수요 순으로 훑을 때 |
