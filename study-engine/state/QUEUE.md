# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

| 망분리 | `network-separation` | **(c) 유형의 원형.** PROMPT.md 가 이 엔진의 존재 이유를 설명하며 **직접 예로 든 낱말**이다(`망분리`, `전문(Flat File)`, `풀업 저항`). 직접 세어 **130건(모집중 51)** 이고 전부 설명 없이 조건으로만 나온다: `On-Premises, 망분리 환경 구축 및 운영 경험`(포밸류소프트), `금융권 대형 SI 프로젝트를 리드한 경험(망분리, 금융 클라우드 이용 가이드라인 대응)`(피에프씨테크놀로지스), `폐쇄망, 망분리, 보안요건이 높은 환경`(이그레브), `망분리 환경의 데이터 반입·연계 프로세스`(위시드). ⚠️ **한국 특유의 규제 개념이라 영어 자료가 사실상 없다 — 이 엔진이 아니면 아무도 안 쓴다.** 축은 ① **왜 생겼나**(금융·공공 규제. 물리적 망분리와 논리적 망분리) ② **개발자에게 실제로 무엇이 바뀌나** — 인터넷이 없는 곳에서 빌드하기(사내 미러·오프라인 패키지), 코드·데이터 **반입/반출 절차**, 외부 API 를 못 부르는 설계 ③ **VLAN·ip rule 같은 구현 층**(포티투닷 공고가 그 표현을 쓴다) ④ **개발 생산성과의 맞바꿈** | ⚠️ **규제 문서를 직접 인용해야 하는 첫 낱말이다** — 금융감독원·금융보안원의 전자금융감독규정 관련 공개 자료를 `WebSearch` 로 찾아 **조문 번호를 확인하고** 건다. 못 찾으면 **찾지 못했다는 사실을 `open_questions` 에 적고** 공고 문장으로만 받친다. **법·규제를 지어내면 이 엔진에서 가장 나쁜 오류다** |
| gRPC | `grpc` | **(c).** 직접 세어 **240건(모집중 125)** 이고 역시 나열형이다: `REST API 설계 및 gRPC 등 RPC Framework 기반 서비스 연동`(에이아이트릭스), `gRPC/Protobuf 기반 API 설계 경험 (ConnectRPC, buf 등)`(에어스메디컬), `메시징 프레임워크의 이해 (DDS, GRPC, Some/IP, MQTT 등)`(포티투닷 — **차량 쪽**), `Go/gRPC 기반의 개발 경험`(사줘). **이 백과사전에 REST 문서가 없다는 점이 오히려 기회다** — REST 를 설명하는 문서는 넘치므로, **"왜 REST 대신 이것인가"** 를 축으로 잡으면 겹치지 않는다. ① **스키마가 먼저다**(protobuf IDL → 코드 생성. `jpa`·`spring` 의 '규약을 코드로 굳힌다'와 같은 계열) ② **바이너리 + HTTP/2 멀티플렉싱**이 무엇을 바꾸나 ③ **스트리밍 네 가지**(단항·서버·클라이언트·양방향 — `mqtt`·WebSocket 과의 자리 구분) ④ **브라우저에서 그냥 못 쓴다**(gRPC-Web/ConnectRPC 가 왜 있나) ⑤ **필드 번호와 하위 호환**(스키마 진화 규칙 — 이게 실무에서 가장 자주 사고 난다) | gRPC 공식 문서 + **Protocol Buffers 언어 가이드**(필드 번호·호환 규칙)가 1차 자료다. **URL 은 `WebSearch` 로 확인하고 건다** |
