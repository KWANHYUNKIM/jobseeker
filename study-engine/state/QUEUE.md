# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

## 대기

| 낱말 | slug | 왜 이 낱말 | 무엇을 읽을 수 있나 |
|---|---|---|---|



| API 버전 관리와 폐기 | `api-versioning` | **세 문서가 같은 자리를 가리킨다** — `openapi`(공개 API 에서 계약 테스트를 못 쓸 때 남는 유일한 수단), `contract-testing`("명세 기반 검증 + **버전 정책 + 폐기 예고**"), `data-contract`(호환성 유형은 정했는데 **깨야 할 때 어떻게 하나**는 안 다뤘다). ⭐ **'여러 문서가 멈춘 자리'는 공고 수가 적어도 값이 크다**(`load-test` 때의 규칙) — 그런데 이번엔 수요도 있다: **240건(모집중 89)**. 근거: 인티그레이션 `프론트엔드와 공유하는 **API·스키마 계약의 하위 호환성을 관리**하고, 여러 저장소에 걸친 변경을 안전하게 배포합니다`, 왓섭 `API 버전 관리 및 서비스 규모 확장 대응`, 딜라이트룸 `버전 관리, **하위 호환성**, 배포 및 마이그레이션 전략을 수립하고 운영해요`, 클레온 `외부 배포용 SDK/라이브러리 운영 경험 (**버저닝, 하위 호환**, ProGuard 규칙, 문서화)`. ⚠️⚠️ **`폐기` 가 오탐 덩어리다** — 녹음 파일 폐기·재고 폐기 리스크가 걸린다. ⚠️ `버저닝` 도 **데이터셋 버저닝**(위즈코어)이 섞인다. `감사`·`관제`·`토큰화` 규칙 그대로 **문장을 읽고 센다.** 축: ①**버전을 어디에 두나**(URL 경로 `/v2/` vs 헤더 vs 미디어 타입 — 각각의 대가) ②⭐**버전을 올리지 않는 것이 최선이다**(`data-contract` 의 호환 규칙으로 버티는 것이 1순위, 버전은 실패의 인정이다) ③**두 버전을 동시에 운영하는 비용**(코드 분기·테스트·장애 조사가 두 배 → `feature-flag` 의 그 대가) ④**폐기 절차**(예고 → 사용량 계측 → 경고 헤더 → 차단. **누가 아직 쓰는지 모르면 못 끈다** → `lineage`) ⑤**클라이언트를 통제할 수 없을 때**(모바일 앱은 강제 업데이트 말고 방법이 없다 — 국내 공고에 흔한 상황) | ⭐ **1차 자료 후보** — **Stripe·GitHub·AWS 의 API 버전 정책 문서**가 공개 HTML 이고 **각자 다른 방식을 택해 그 이유를 적어 뒀다**(Stripe 는 날짜 기반 고정, GitHub 은 헤더, AWS 는 서비스별). **서로 다른 세 제품을 겹쳐 읽어 비교표를 만드는 방식**(`causal-consistency`·`replication`·`audit-log` 에서 세 번 통했다)이 이 낱말에 가장 잘 맞는다. 보조로 **RFC 8594(Sunset HTTP 헤더)** — 폐기 예고의 표준이 있다 |
| 보안 인증 제도 (KCMVP·CC·ISMS-P) | `security-certification` | **`encryption` 이 `korea` 절에서 열었다가 1차 자료가 없어 "이름이 나온다"까지만 쓰고 닫은 자리**다. 그리고 **`network-separation`(규제) · `audit-log`(FDA·HIPAA·ISO 42001) · `dlp`(개인정보보호법)가 전부 규정을 언급만 하고 지나갔다** — 이 백과사전에 **제도를 정면으로 다루는 문서가 하나도 없다.** 근거: 아이씨티케이 `보안 인증 : **CC, KCMVP, FIPS 140** 등 보안 인증 획득 과정 참여 또는 관련 지식 보유`, 노드인프라 `**CC, GS, KCMVP** 등 제품 보안 인증서 취득 및 갱신`, 브레인다이브 `**KCMVP 암호모듈** 연동`, 웰리시스 `미국 FDA, HIPAA, 유럽 CE`, 에버엑스 `ISO/IEC 42001(AIMS)`. ⚠️ **근거가 얇다**(KCMVP 계열 8건) — `rebac`·`contract-testing` 처럼 **왜 얇은지를 숫자로 적고 쓴다.** ⚠️⚠️ **`인증` 은 한국어에서 최악의 겹침**(authentication vs certification) — `감사`·`관제` 보다 심할 수 있으니 **제도 이름으로만 세고 문장을 읽는다.** 축: ①**인증(authentication)과 인증(certification)은 다른 말이다**(첫 절이 그 구분) ②**무엇을 인증하나**(제품 vs 조직 vs 사람 — CC·KCMVP 는 제품, ISMS-P 는 조직) ③⭐**인증이 구현을 제한한다**(검증된 모듈만 써야 하면 라이브러리 선택이 사라진다 → `encryption` 의 그 지점) ④**갱신이 본체다**(취득보다 유지가 길다 — 노드인프라가 `취득 및 **갱신**` 이라 적는다) ⑤**어느 시장에 파느냐가 목록을 정한다**(국내 KCMVP·GS, 해외 CC·FIPS 140) | ⭐ **1차 자료 후보** — **NIST CMVP(FIPS 140) 페이지**가 공개 HTML 이고 **검증된 모듈 목록을 실제로 조회할 수 있다**(`rbac` 의 NIST CSRC 처리와 같은 형태). **Common Criteria 포털**도 공개. ⚠️ **국내 제도(KCMVP·ISMS-P·GS)는 소관 기관 페이지를 찾되 PDF·유료면 `ohms-law`·`network-separation` 처리**(공개 요약·기관 페이지로 대신하고 밝힌다). ⚠️ **`encryption` 과 겹치지 않게 — 알고리즘·키는 그쪽, 여기는 제도** |
