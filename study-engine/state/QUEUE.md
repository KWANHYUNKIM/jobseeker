# 대기열 — 쓸 낱말

`validate.py --gaps` 의 사다리 3순위가 이 파일의 "대기" 표 **맨 위 한 줄**을 읽는다.
표의 첫 열(낱말)만 기계가 읽는다 — 나머지 열은 사람과 다음 사이클을 위한 근거다.

> ⚠️ 이 문서를 스크립트로 고칠 때 `s.index("## 대기")` 로 자르지 말 것.
> 위 문장에 같은 글자가 있어 인트로 한가운데를 잘라 먹는다. `"\n## 대기"`(줄 시작)로 찾는다.

큐에 올릴 자격은 셋 중 하나다 (PROMPT.md 2⁗단계).
**(a) 수요가 큰데 문서가 없다** / **(b) 이미 쓴 문서가 계속 가리킨다(끊긴 `related`)** /
**(c) 공고·블로그에는 나오는데 어디에도 설명이 없는 말.**

## 대기

| 낱말 | slug | 왜 이 낱말 | 무엇을 읽을 수 있나 |
|---|---|---|---|
| GIL | `gil` | **(b) 끊긴 링크 — `python` 이 "가장 많이 인용되는 한 낱말"이라며 가리킨다.** 파이썬 문서에서 스레드·프로세스·asyncio 선택의 근거가 전부 이 낱말 하나로 수렴했는데, 정작 *왜 그런 잠금이 생겼고 왜 아직 못 걷어내는지*는 거기 두 문단으로 눌러 담았다. 참조 카운팅 → 잠금 방식의 선택 → C 확장 생태계가 그 위에 지어진 사정 → PEP 703 의 자유 스레드 빌드까지가 본체다. **면접에서 파이썬 동시성을 물으면 결국 이 이야기를 시킨다** | 1차 자료가 두껍다 — Python 용어집의 GIL 정의, PEP 703 원문(설계 근거와 성능 대가가 다 적혀 있다), `threading`·`multiprocessing` 문서. 실습은 `python` 문서의 두 번째 drill(스레드 vs 프로세스 시간 재기)을 그대로 이어 쓴다 |
| asyncio | `asyncio` | **(b) 끊긴 링크.** `python` 이 "이벤트 루프·코루틴·run_in_executor 의 본체"라며 넘겼다. **(c) 공고 근거가 두껍다** — `asyncio 비동기 프로그래밍 경험이 있는 분`(미켈로로보틱스), `FastAPI 등 비동기 웹 프레임워크 경험 우대`(누리미디어), `FastAPI / Uvicorn 기반 비동기 웹 서버 개발 경험` 등 모집중 다수. 축은 **"왜 async 로 물드는가"** — 한 번 async 를 들이면 호출 사슬 전체가 따라오는 성질(function color), 블로킹 한 줄이 서버를 세우는 구조, `gather`·태스크 취소·타임아웃 | asyncio 공식 문서(1차), PEP 492(async/await 도입), Uvicorn·FastAPI 문서. `python` 문서의 세 번째 drill(sleep 두 종류로 동시 요청 재기)이 그대로 이 문서의 입구다 |
| Java | `java` | **(b) 끊긴 링크이자 자리 예약.** `java-in-finance` 가 "언어 자체는 여기"라며 넘겼고, **`Java` 라는 alias 를 일부러 비워 뒀다** — 그 문서가 alias 를 가져가면 이 문서가 영영 관계 화면에 못 걸린다. **(a) 수요 2위**(공고 1,655건 · 22.1% · 동반 Spring 44.5%)라 `market` 이 채워질 문서다. 축은 **JVM 이 만든 성질** — 하위 호환성, GC 와 힙 튜닝, 한 번 정한 LTS 를 오래 끌고 가는 이유, Kotlin 이 같은 런타임에서 무엇을 바꿨나 | Oracle Java SE 지원 로드맵(LTS 표), JEP·JLS, Spring 공식 문서. 금융 쪽 맥락은 이미 `java-in-finance` 에 있으니 **거기와 겹치지 않게 언어·런타임만** 쓴다 |
| STM32 | `stm32` | **(b) 끊긴 링크 — 두 문서가 가리킨다**(`atmega128` 의 "다음 자리", `gpio-register` 의 가운데 열). **미룸에서 올라왔다** — 조건이었던 `gpio-register` 를 끝냈으므로 이제 비교할 자리가 있다. **(c) 공고 근거가 두껍다**: `마이크로컨트롤러(STM32, AVR 등)`, `MCU (AVR, ESP32, STM32 등)` 처럼 세 칩이 한 줄에 묶여 나온다. 축은 **AVR 에 없던 것들** — 클럭 트리와 RCC(왜 클럭부터 켜야 하나), 시리즈 파편화(F1 의 CRL/CRH vs F4 의 MODER), HAL/LL/CubeMX 의 층, NVIC | ST 레퍼런스 매뉴얼(RM0008·RM0090은 이미 `gpio-register` 에서 인용했다), ST 의 HAL 문서. **`gpio-register` 와 겹치지 않게** GPIO 는 링크로 넘기고 클럭·인터럽트 컨트롤러·툴체인 쪽을 쓴다 |
| SPI | `spi` | **(b) 끊긴 링크.** `i2c` 의 비교표가 가운데 열을 통째로 비워 뒀다("속도가 필요할 때 가는 곳"). **(c) 공고에서 I²C·UART 와 늘 한 줄에 묶여 나온다** — `시리얼 통신 프로토콜(UART, SPI, I2C) 구현 경험` 류가 모집중 다수. 축은 **I²C 가 못 하는 것을 어떻게 하는가** — CS 로 고르는 방식(주소가 없다), 전이중, 클럭 모드(CPOL/CPHA)라는 악명 높은 함정, 데이지 체인. `i2c` 문서가 이미 비교표와 '선을 줄이는 비용' 틀을 세워 뒀으므로 **그 틀을 그대로 뒤집어 쓰면 된다** | 부품 데이터시트의 SPI 타이밍도(모드 0~3), MCU 레퍼런스 매뉴얼의 SPI 절. ⚠️ SPI 는 **단일 규격 문서가 없다**(모토로라 관행에서 굳어졌다) — 그 사실 자체를 문서에 적어야 한다. 1차 자료는 벤더 문서뿐 |
| RTOS | `rtos` | **(b) 끊긴 링크 — `interrupt` 가 마지막 절에서 결론으로 가리킨다**("ISR 이 늘어 최악 지연을 사람이 못 따라갈 때 올라가는 층"). **(c) 공고 근거가 이 계열에서 가장 두껍다** — `RTOS(FreeRTOS, Zephyr 등) 활용 경험`(디하이브), `RTOS 기반 멀티태스킹 환경 개발 경험자`(신성테크), `RTOS 포팅 및 개발 역량`(엑소시스템즈), `RTOS 사용 경험 우대`(BNSR) 등 모집중 다수. 축은 **인터럽트로 안 되는 것부터** — 우선순위 역전, 태스크와 ISR 의 경계(ISR 안에서 부를 수 있는 API 가 따로 있다), 뮤텍스·세마포어·큐, 스택을 태스크마다 따로 잡는 문제, 그리고 '실시간'이 빠름이 아니라 **최악 시간 보장**이라는 정의 | FreeRTOS 공식 문서(freertos.org)와 Zephyr 문서(docs.zephyrproject.org) — **URL 은 `WebSearch` 로 확인하고 건다.** `interrupt` 문서가 이미 지연·원자성·짧은 ISR 규칙을 깔아 뒀으므로 **그것과 겹치지 않게** 스케줄링 쪽을 쓴다 |
| Modbus | `modbus` | **(b) 끊긴 링크 — `rs485` 가 "이 전선 위에서 실제로 도는 프로토콜"이라며 넘겼다.** **(c) 공고에 설명 없이 등장하는 낱말의 대표**다 — `Modbus, CAN 등 산업 통신 프로토콜`(스탠다드에너지), `산업용 프로토콜(OPC-UA, Modbus 등)`(지신), `Modbus, MQTT, TCP/IP 소켓 통신 등 디바이스-서버 간 통신 프로토콜을 직접 설계하거나 구현해본 경험`(헤리트), `Modbus, SSH/SFTP, ZeroMQ`(미켈로로보틱스). 축은 **레지스터 모델**(코일/입력/보유 레지스터의 구분과 주소 오프셋 1 차이 함정), 기능 코드, **CRC-16**, RTU vs ASCII, 3.5문자 침묵으로 프레임을 가르는 방식, 예외 응답. `rs485` 의 세 번째 실습(프레임 손으로 만들기)이 이 문서의 입구다 | **modbus.org 사양서**(`MODBUS over Serial Line V1.02`, `MODBUS Application Protocol V1.1b3`) — 공식이지만 **다운로드에 동의 절차가 있을 수 있다.** 그 경우 `rs485` 때처럼 URL·문서 신원까지만 확인하고 못 대조한 것은 `open_questions` 에 적는다. 장비 매뉴얼의 레지스터 표도 좋은 2차 근거다 |
| 멱등성 | `idempotency` | **(c) 회의에서 그냥 쓰이는 말.** 결제·주문 공고의 자격요건에 `멱등성`이 설명 없이 등장한다. 재시도·중복 요청·네트워크 타임아웃과 한 몸이라 백엔드 면접의 단골이기도 하다. 정의는 한 줄인데 *언제 멱등키를 쓰고 언제 분산 락을 쓰나*를 가른 글은 드물다 | HTTP 메서드 정의(RFC 9110), Stripe·Toss 결제 API 의 idempotency key 문서, 국내 커머스 기술블로그의 재시도 글 |
