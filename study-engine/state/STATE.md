**이 엔진의 첫 `domain`(도메인 상식) 문서다.** 앞의 넷과 성격이 다르니 아래를 지킨다.

- **기술 설명서가 되면 실패다.** "JVM 이 무엇인가"는 이 문서의 일이 아니다. 물음은
  *왜 하필 금융권에서 유독 Java 인가* 하나이고, 답은 기술보다 **제도·자산·인력 시장**에 있다.
- **`confirmed` 로 쓸 수 있는 것과 아닌 것을 엄격히 가른다.** 전자금융감독규정·금융보안원
  가이드처럼 **원문이 공개된 것만** confirmed 다. "SI 관행상 그렇다" 류는 전부 `inferred`.
- **회사·업계 평가 금지**(PROMPT.md 공개 사이트 규칙). "금융권은 보수적이라 느리다" 같은
  문장을 쓰지 않는다. 제도가 무엇을 요구하는지와 그 결과로 무엇이 선택됐는지만 쓴다.
- **공고 근거는 이미 확보돼 있다.** 브리핑 엔진의 포밸류소프트 건이 같은 벽을 만났다 —
  `망분리`·`전문(Flat File)`·`AES/SEED/ARIA`·`Tibero` 가 자격요건 원문에 박혀 있고,
  NH농협 차수 사업이 실명으로 나온다. `jd-viewer/public/guide/companies/4valuesoft.json`
  과 공고 본문 검색(`망분리|전자금융|코어뱅킹|차세대`)에서 evidence 를 뽑는다.
- **`market` 은 채운다.** Java 는 `tech_relations.json` 에 있다 — `count 1655` ·
  `pct_jobs 22.1` · `layer 언어` · 동반 Spring 44.5 · AWS 38.0 · Python 34.7 ·

## 배운 것

- **`market` 이 있는 문서는 동반 기술이 목차를 정해 준다.** Python 의 AWS 36.0 ·
  Docker 24.5 · K8s 23.9 를 보고 "한 프로세스로 코어를 다 못 쓰니 워커 수로 규모를 낸다"는
  절을 세웠다. 숫자를 표에 박아 두고 끝내지 말고 **본문이 그 숫자를 다시 인용하게** 쓴다.
- **`market` 은 비는 게 정상인 낱말이 있다.** 앞의 셋(atmega128·풀업 저항·UART)이 그랬다.
  그런 문서는 수요 근거를 `evidence`(공고 원문)로 대신하고 `open_questions` 에 남긴다.
- **낱말이 공고에 안 걸리면 그 낱말이 전제되는 문장을 찾는다.** `풀업` 은 0건이었지만
  `I2C`·`회로도 독해` 로 걸렸다. 반대로 `UART|시리얼|Serial` 은 339건, Python 계열
  선택 문장(asyncio·Celery·FastAPI·pandas)은 997건으로 넉넉했다.
- **표준·벤치마크 숫자는 조심해서 쓴다.** 유료 표준(IEC 60062, TIA/EIA-485)은 링크를
  지어내지 않고 사정을 적는다. 벤치마크 수치(3.11 성능)는 워크로드 의존이라 배수를
  적지 않고 `open_questions` 에 남겼다.
- **숫자 표는 계산해서 넣는다.** UART 의 UBRR 오차표는 파이썬으로 직접 계산해 채웠다.
- **한 문서가 다음 큐를 만든다.** 지금까지 끊긴 링크로 큐에 오른 것: `i2c`·`ohms-law`
  (풀업), `interrupt`·`rs485`(UART), `gil`·`asyncio`(Python). 큐가 마르지 않는다.
