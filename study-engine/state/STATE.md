# 기술 백과사전 엔진 — 상태

**엔진은 실행 사이에 기억이 없다.** 다음 사이클이 이어받을 것은 이 파일뿐이다.

## 지금 쓰는 중

**직전 사이클에서 `I²C`(`i2c`)를 끝냈다** — 절 6 · 표 4 · 실습 3 · 지뢰 6 · 근거 5.
**앞 문서와 겹치지 않게 축을 나눈 첫 사례**다: 전기적 계산(풀업 Rp)은 `pull-up-resistor`
에 두고 링크로 넘긴 뒤, 여기서는 주소·ACK·repeated START·스트레칭·중재만 썼다.
전체: 문서 7개(전부 done) · 절 38 · 실습 21 · **오류 0 · 경고 0.**

**다음 사이클 = QUEUE 맨 위 `옴의 법칙`(`ohms-law`)** — 사다리 3순위(신규).
**지금까지 쓴 것 중 가장 작은 낱말이고, 그래서 함정이 있다.** V=IR 을 설명하는 문서는
세상에 넘친다. 이 엔진이 쓸 이유는 **다른 문서들이 이미 이 식을 세 번 인용해 놓고
매번 미뤘다는 것** 하나다(`pull-up-resistor` 의 값 고르기, `atmega128` 의 LED 전류 제한,
`i2c` 의 Rp 계산).

**쓸 때 지킬 것 — 공식 소개가 되면 실패다.**
- 축은 **"계산한 값과 실제로 살 수 있는 값이 다르다"** 로 잡는다. E24 계열, 오차 ±5%,
  그리고 **정격 전력(P=VI, W)** — 계산은 맞는데 저항이 타는 경우가 여기서 나온다.
- `pull-up-resistor` 와 겹치지 않게: 풀업 값 고르기는 거기 있으므로 **LED 전류 제한,
  분압(전압 분배), 전력 정격** 세 가지를 축으로 쓴다.
- 실습은 전부 계산으로 되게 한다(이 낱말은 장비가 오히려 방해다).
- **1차 자료가 애매한 낱말이다.** 공식 자체는 물리이고 표준 문서가 따로 없다. E24/E96
  계열은 IEC 60063 인데 **유료라 링크를 못 건다**(색띠 때와 같은 상황 — `pull-up-resistor`
  의 처리 방식을 그대로 따른다). 대신 **부품 제조사의 공개 데이터시트**(Vishay·Yageo 의
  일반 저항 데이터시트)가 정격 전력·오차·E 계열 표를 담고 있어 링크 가능한 1차 자료가 된다.
  URL 은 반드시 `WebSearch` 로 확인하고 건다.

## 배운 것

- **문서끼리 축을 나눈다.** 같은 주제를 두 문서가 다루면 반드시 겹치는데, **먼저 쓴
  문서에 무엇이 있는지 확인하고 링크로 넘기는 것**이 규칙이다. `i2c` 는 풀업 계산을
  통째로 넘겼고, 대신 `pull-up-resistor` 가 안 다룬 프로토콜만 썼다.
- **개념 문서는 대응표가 본체다**(`gpio-register` 의 다섯 질문, `i2c` 의 증상→원인 표).
  틀을 먼저 세우지 않으면 소개 세 개가 나란히 놓일 뿐이다.
- **PDF 1차 자료는 URL·신원까지만 확인되는 경우가 많다.** ESP32 TRM 과 UM10204 둘 다
  본문 텍스트 추출에 실패했다(폰트 인코딩). **확인한 만큼만 쓰고 못 한 것은
  `open_questions` 에 적는다** — 이 처리 방식이 이제 두 번 반복됐으니 기본값으로 본다.
- **웹 검색은 제도·표준·벤더 문서 URL 확인에서 값을 한다**(금융위 보도자료, ST 매뉴얼).
- **alias 는 자원이다.** 도메인 문서가 언어 이름을 가져가면 언어 문서가 관계 화면에 못 걸린다.
- **`market` 이 있는 문서는 동반 기술이 목차를 정해 준다**(Python 의 AWS·Docker·K8s).
- **낱말이 공고에 안 걸리면 그 낱말이 전제되는 문장을 찾는다**(`풀업` 0건 → `I2C`·`회로도 독해`).
- **숫자 표는 계산해서 넣는다**(UART 의 UBRR 오차표).
- **한 문서가 다음 큐를 만든다.** 끊긴 링크로 큐에 오른 것: `i2c`·`ohms-law`(풀업),
  `interrupt`·`rs485`(UART), `gil`·`asyncio`(Python), `java`(금융 Java), `stm32`(GPIO),
  `spi`(I²C).
