# 기술 백과사전 엔진 — 상태

**엔진은 실행 사이에 기억이 없다.** 다음 사이클이 이어받을 것은 이 파일뿐이다.

## 지금 쓰는 중

**직전 사이클도 네 문서를 병렬로 썼다** — 사용자 지시. `java` · `stm32` · `spi` ·
`idempotency`. 그 앞 사이클(`interrupt` · `rs485` · `gil` · `asyncio`)과 같은 방식이다.
전체: 문서 **16개(전부 done)** · 절 **95** · 실습 **52** · **오류 0 · 경고 0.**

**병렬로 돌릴 때의 규칙 — 두 번 돌려 보고 굳은 것.**
각 실행은 **자기 `articles/<slug>.json` 하나만** 쓴다. `index.json` · `QUEUE.md` ·
`STATE.md` 는 손대지 않고 `git` 도 `validate.py` 도 돌리지 않는다(셋 다 공유 자원이라
동시에 쓰면 서로 덮어쓴다). 병합·검증·커밋은 한 곳에서 한다. 겹침은 **이웃 문서를
먼저 읽히고 "무엇을 그쪽으로 넘길지"를 지정**해서 막는다 — 이번엔 `gpio-register` 의
GPIO 표(→ stm32 는 링크만), `i2c` 의 비교표 틀(→ spi 가 뒤집어 씀), `java-in-finance`
의 금융 맥락(→ java 는 언어·런타임만)을 배정했다.

**병렬의 값이 실제로 어디서 나오는지도 보였다.** 네 문서가 각자 만든 끊긴 링크가
한꺼번에 큐가 된다 — 이번엔 6개(`distributed-lock` · `spring` · `kotlin` ·
`garbage-collection` · `kafka` · `outbox-pattern`). 순차로 돌면 이게 네 사이클에 걸쳐
하나씩 나온다.

**다음 사이클 = QUEUE 맨 위 `Modbus`(`modbus`)** — 사다리 3순위(신규).
`rs485` 가 "주소와 프레임을 주는 위층"이라며 가리킨 자리다. 모집중 공고에서 **Modbus
72건 vs RS-485 30건**으로 오히려 위층이 더 많이 불린다. `rs485` 가 이미 받아 인용한
`Modbus over Serial Line V1.02` 를 그대로 쓸 수 있고(공개 PDF), 겹치지 않게 **전기
규격은 rs485 로 넘기고** RTU/TCP 갈림·레지스터 4종·주소 1-based 혼란을 쓴다.

## 배운 것

- **`needs` 는 장비가 아닐 때도 `no_hardware` 를 요구받는다.** `idempotency` 3건과
  `java` 2건이 "JDK 하나" 같은 소프트웨어를 `needs` 에 적었다가 경고 5건으로 걸렸다.
  검증기는 장비와 설치물을 구분하지 않는다. **규칙을 느슨하게 고치지 말고**, 설치
  없이 같은 것을 확인하는 대안을 실제로 적는 편이 문서에도 낫다(예측을 먼저 적어 두고
  나중에 맞춰 보게 하는 식).
- **alias 중복은 각 실행이 자기 것만 확인할 수 있다.** 배치끼리 부딪혔는지는 **병합
  시점에만 보인다** — index 전체의 alias 를 소문자로 모아 세는 절차를 병합에 넣었다.
  이번 배치는 충돌 0. 앞 배치는 `uart`↔`rs485` 의 `RS-485` 가 걸렸었다.
- **약어는 다른 동네에서 이미 쓰인다.** `ISR`(→ Next.js Incremental Static
  Regeneration)에 이어 `SPI` 도 48건 중 3건이 동음이의였다(Keycloak Service Provider
  Interface, 솔더 페이스트 검사). **직접 셀 때 문맥을 보고 세라.**
- **PDF 1차 자료는 이제 기본으로 뚫는다.** `curl` + `pdftotext -layout` 로 이번에
  M68HC11 레퍼런스 매뉴얼(SPI 의 원본 정의), RM0008/RM0090/PM0214/UM1725/AN2606,
  W25Q128JV·BME280·SN74HC595 데이터시트 본문을 확인했다. **벤더 서버가 막으면
  (st.com 은 curl·WebFetch 둘 다 타임아웃, oracle.com 은 WebFetch 403) 대학·공개
  미러나 `curl` 로 우회한다.** 다만 **판본이 현행과 다를 수 있다는 사실을
  `open_questions` 에 남긴다.**
- **자료끼리 숫자가 어긋나면 합치지 말고 나열한다.** 이번엔 멱등키 규격(Stripe 24시간
  ·255자 vs 토스 15일·300자)을 출처별 표로 남겼다. 앞 사이클의 GIL 오버헤드·RS-485
  종단값과 같은 처리다.
- **"없다"를 증명하지 말고 "못 찾았다"고 써라.** `spi` 는 단일 규격 문서가 없다는
  통설을 **증명한 게 아니라 못 찾은 것**이라고 명시하고 근거 3가지만 적었다.
- **`market` 의 `as_of` 는 문서를 쓴 날이 아니라 `tech_relations.json` 의
  `generated_at` 이다.** 지난 사이클에 `python` 에서 틀렸던 자리인데 `java` 는 맞게
  넣었다(2026-08-19). QUEUE 에 적힌 수요 숫자도 낡는다 — Java 는 1,655건/22.1% 로
  적혀 있었지만 실제는 **2,174건/23.0%** 였다. **쓰기 전에 파일에서 다시 확인한다.**
- **낱말이 모집중 공고에 안 걸릴 때가 있다.** `GIL` 은 마감 공고를 쓰되 `where` 에
  밝혔고, `옴의 법칙` 은 그 말이 전제되는 문장으로 받쳤다. 선택지가 둘이다.
- **문서끼리 축을 나눈다.** 먼저 쓴 문서에 무엇이 있는지 확인하고 링크로 넘긴다.
  `stm32` 는 GPIO 를 `gpio-register` 로, 인터럽트 개념을 `interrupt` 로 넘기고
  클럭 트리·NVIC 구조·HAL 층만 썼다.
- **개념 문서는 대응표가 본체다** — `idempotency` 의 세 갈래 비교표(멱등키 · 분산 락 ·
  DB 유니크 제약), `spi` 의 모드 0~3 표, `stm32` 의 AVR 에 없던 축 11가지.
- **유료 표준이 반복해서 걸린다**(IEC 60062·60063, TIA/EIA-485). 링크를 지어내지 않고
  **제조사 데이터시트를 대신 인용**하는 것이 정해진 처리다.
