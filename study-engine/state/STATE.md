# 기술 백과사전 엔진 — 상태

**엔진은 실행 사이에 기억이 없다.** 다음 사이클이 이어받을 것은 이 파일뿐이다.

## 지금 쓰는 중

**직전 사이클은 예외적으로 네 문서를 한 번에 썼다** — 사용자가 병렬 실행을 지시했다.
`interrupt` · `rs485` · `gil` · `asyncio` 넷을 각각 다른 실행에 맡기고, `index.json` ·
`QUEUE.md` · `STATE.md` 병합과 검증·커밋은 한 곳에서 했다. 전체: 문서 **12개(전부 done)** ·
절 **69** · 실습 **37** · **오류 0 · 경고 0.**

**병렬로 돌릴 때의 규칙 — 이번에 실제로 통한 방식.**
각 실행은 **자기 `articles/<slug>.json` 하나만** 쓴다. `index.json` · `QUEUE.md` ·
`STATE.md` 는 손대지 않고, `git` 도 `validate.py` 도 돌리지 않는다(그 셋은 전부 공유
자원이라 동시에 쓰면 서로 덮어쓴다). 대신 각 실행에 **이웃 문서를 먼저 읽히고**
"무엇을 그쪽으로 넘길지"를 지정해 줘야 겹치지 않는다. 이번엔 `uart` 의 오버런,
`gpio-register` 의 read-modify-write, `python` 의 drill 셋을 미리 배정했다.

**직전 사이클에서 함께 처리한 것 — 미결이던 경고 2건이 사라졌다.**
`python.json` 의 `market` 을 지금 `tech_relations.json` 값으로 맞췄다(공고 2,648 →
**3,054**, 35.4% → **32.3%**, 동반 기술 비율도 함께). **`as_of` 를 문서를 쓴 날이 아니라
`tech_relations.json` 의 `generated_at`(2026-08-19)으로 바로잡았다** — 그래야 다음
사이클이 무엇과 대조할지 안다. 앞으로 `market` 있는 문서를 쓸 때 이 규칙을 지킨다.

**다음 사이클 = QUEUE 맨 위 `Java`(`java`)** — 사다리 3순위(신규).
`java-in-finance` 가 `Java` alias 를 **일부러 비워 두고** 기다리는 자리다. 금융 맥락은
그 문서에 이미 있으니 **언어·런타임만** 쓴다 — JVM 이 만든 성질(하위 호환성, GC 와 힙,
LTS 를 오래 끄는 이유, Kotlin 이 같은 런타임에서 바꾼 것). `market` 이 채워질 문서다
(공고 1,655건 · 22.1% — 쓰기 전에 `tech_relations.json` 에서 **지금 값을 다시 확인**할 것).

## 배운 것

- **alias 는 자원이고, 새 문서는 남의 alias 를 빼앗는다.** `rs485` 를 쓰는 순간
  `uart.json` 이 쥐고 있던 `RS-485` 가 충돌했다(병합 때 uart 에서 뺐다). **새 문서를
  넣을 때 index 전체의 alias 중복을 반드시 한 번 세라** — 조용히 깨지고, 깨져도
  validate 가 아니라 화면에서만 티가 난다.
- **약어는 다른 동네에서 이미 쓰이고 있을 수 있다.** `ISR` 을 인터럽트 문서의 alias 로
  걸 뻔했는데, 국내 공고에서 `ISR` 은 압도적으로 Next.js 의 Incremental Static
  Regeneration 이다(프론트엔드 공고 15건 이상). **alias 후보는 공고 본문에서 한 번
  검색해 보고 넣는다.**
- **1차 자료 URL 은 미러가 죽는다.** avr-libc 의 nongnu 미러가 429 로 계속 막혀
  `avrdudes.github.io` 의 현행 배포처로 갈아탔다. **막히면 같은 문서의 다른 배포처를
  찾는다**(지어내지 말고, 두 문면의 차이는 `open_questions` 에).
- **PDF 1차 자료는 이제 추출된다.** WebFetch 가 저장한 PDF 를 `pdftotext`/`pypdf` 로
  열어 ATmega128 데이터시트의 인터럽트 벡터 표·클럭 수를, TI SLLA272D 와 Modbus
  사양서의 숫자를 직접 대조했다. **"PDF 라서 URL 까지만" 은 더 이상 기본값이 아니다.**
- **자료끼리 숫자가 어긋나면 합치지 말고 나열한다.** GIL 오버헤드(PEP 703 6%/5% ·
  PEP 779 "around 10%" · 3.14 문서 "roughly 5-10%")와 RS-485 종단값(TI 120Ω vs
  Modbus 150Ω)을 **출처별 대조표**로 남기고 단정하지 않았다. 평균을 내는 순간 어느
  자료에도 없는 숫자가 생긴다.
- **낱말이 모집중 공고에 안 걸릴 때가 있다.** `GIL` 은 active 공고에 직접 요구하는
  문장이 없어 **마감된 공고 1건**을 쓰되 `where` 에 마감임을 밝혔다. 앞의 `옴의 법칙`
  처럼 "그 말이 전제되는 문장"으로 받치는 방법과 함께, 이제 선택지가 둘이다.
- **문서끼리 축을 나눈다.** 같은 주제를 두 문서가 다루면 반드시 겹치므로, **먼저 쓴
  문서에 무엇이 있는지 확인하고 링크로 넘긴다.** `i2c` 는 풀업 계산을, `ohms-law` 는
  풀업 값 고르기를 각각 `pull-up-resistor` 로 넘겼다.
- **작은 낱말은 "왜 지금까지 미뤘나"가 곧 축이다.** `ohms-law` 는 공식이 아니라
  *계산값 vs 살 수 있는 값(E24)*, *±5% 오차*, *정격 전력* 셋으로 썼다.
- **개념 문서는 대응표가 본체다**(`gpio-register` 의 다섯 질문, `i2c` 의 증상→원인 표,
  `asyncio` 의 블로킹 호출→async 대체 표).
- **유료 표준이 반복해서 걸린다** — IEC 60062(색띠), IEC 60063(E24), TIA/EIA-485.
  링크를 지어내지 않고 **제조사 데이터시트를 대신 인용**하는 것이 정해진 처리다.
- **`market` 이 있는 문서는 동반 기술이 목차를 정해 준다.** 대신 그 숫자는 크롤마다
  바뀌므로 **`as_of` 를 `tech_relations.json` 의 `generated_at` 으로 적어야** 다음
  사이클이 대조할 수 있다.
- **한 문서가 다음 큐를 만든다.** 이번에 끊긴 링크로 새로 오른 것:
  `modbus`(rs485) · `rtos`·`dma`·`watchdog`(interrupt) · `multiprocessing`(gil·asyncio) ·
  `fastapi`(asyncio). `reference-counting` 과 `numpy` 는 **미룸**으로 보냈다 — 지금
  쓰면 `gil` 의 한 절과 겹친다.
