# 강의 노트 엔진 — 한 사이클 절차

역설계(`engine/`)가 "그 회사가 어떻게 만들어졌나"라면 여기는 **"요즘 무엇을 어떻게 공부하나"**다.
Stanford·MIT 같은 공개 강의와 국내외 개발 강의 영상을 읽고, 우리 말로 다시 쓴 노트를
`jd-viewer/public/lectures/` 에 쌓는다. 뷰어 `기업정보 > 강의 노트`(`/lectures`)가 읽는다.

Claude 는 영상을 직접 보지도 듣지도 못한다. 그래서 **말은 자막으로, 그림은 장면으로** 읽는다.

## 한 사이클 = 영상 한 편

1. 다음 일감: `python lecture-engine/validate.py --gaps` 맨 위 id. 순서는 `state/QUEUE.md` 에 손으로 올린 것 →
   `paths.json` 로드맵 — **트랙(AI·코딩테스트·백엔드·프론트엔드·디자인·상세페이지·토익)을 한 편씩 번갈아**,
   트랙 안에서는 앞 단계(입문) 과목의 1강부터. 다른 회차가 재료를 받아 쓰는 중인 강의(3시간 안)는 건너뛴다.
   과목 추가: `python lecture-engine/series.py add <재생목록 id> <키> --track <트랙> --school <채널> --code <짧은 이름>
   --term <학기·판> --title "..." [--max N] [--match 정규식]` 한 뒤 `paths.json` 의 알맞은 단계 `series` 에 키를 넣는다
   (넣지 않으면 맨 뒤로 밀린다). 새 강의가 올라왔는지는 `series.py refresh`.
   대기열(`state/QUEUE.md`)이 비면 새 영상을 찾아 덧붙인다 — 우선순위:
   **사용자는 머신러닝·딥러닝 초보다(2026-11-22)** — 어려운 최신 과목보다 정말 알기 쉬운 것을 먼저 찾는다:
   그림·비유로 설명하는 채널, 한국어 입문 강의, 짧은 편으로 나뉜 재생목록. 트랙별로 아래를 찾는다.
   - AI: 입문(3Blue1Brown·StatQuest·모두의 딥러닝·MIT 6.S191) → 실습(Karpathy) → 정규 과목(Stanford·MIT·CMU)
   - 코딩테스트: 유형별 강의(동빈나 등), 자료구조·알고리즘 기초(국내 대학 공개 강의, MIT 6.006)
   - 백엔드: 네트워크·HTTP·DB·스프링 부트 입문(국내 채용은 자바·스프링이 많다), CS50W
   - 프론트엔드: HTML·CSS·자바스크립트·리액트 기초
   - 디자인: 화면 디자인 규칙·UX·피그마·포트폴리오
   - 상세페이지: 포토샵 기초 → 상세페이지 기획 → 포토샵 실습(스마트스토어·쇼핑몰)
   - 토익: 공부법 → 문법 → RC 파트별 → LC
   재생목록 고르는 기준: 공식 채널(재업로드 금지), 자막(공식이나 자동) 있음, 광고·홍보 영상이 섞이면 `--match`·`--max`
   로 거른다. 몇 시간짜리 몰아보기는 빼고 편으로 나뉜 것을 쓴다.
2. 재료 받기: `python lecture-engine/fetch.py <id>` → `catch_capture/var/lectures/<id>/`
   - `meta.json`(제목·길이·챕터·자막 종류) · `transcript.txt`(1분 단위 대본) · `sheets/sNNN.jpg`
     (30초마다 장면 16칸을 한 장에 — 한 장 = 8분, 칸 왼쪽 위 노란 글씨가 영상 속 시각)
3. 읽기: 대본을 처음부터 끝까지 읽고, 인화를 **전부** 본다. 슬라이드·판서에 뜬 그래프·표·수식은
   대본에 없으니 장면에서 읽어 `chapters[].on_screen` 에 적는다.
4. 쓰기: `jd-viewer/public/lectures/items/<id>.json` — 형식은 `schema.json`.
   **깊이 기준(2026-11-20, 사용자 요청 "너무 축약해서 공부가 안 된다")** — 노트는 요약이 아니라
   **영상을 안 본 사람이 이것만 읽고 공부할 수 있는 교재**다. 참고: Princeton COS511 스크라이브 지침
   (빠진 학생도 이해하는 완결된 문장, 받아 적은 메모가 아님), MIT 스크라이브 팁(강의보다 더 잘 설명하라),
   CS231n 공식 노트(강의 하나에 6천 단어 안팎, 개념마다 직관 → 식 → 작은 숫자 예 → 코드 → 주의점).
   - 챕터마다 `explain` 문단 3개 이상·600자 이상: 직관(비유) → 정의 → 왜 그런가 → 강의가 든 예.
     강의가 빠르게 넘어간 곳은 더 풀어 쓴다. 노트 전체 본문은 강의 1분당 200자 이상(validate 가 센다).
   - 식이 나오면 `formulas` 에 기호 하나하나의 뜻까지. 식이 있는 챕터는 `example` 로 작은 숫자를 직접 넣어 본다.
   - 코드로 확인할 수 있는 개념은 `code`(직접 쓴 30줄 안쪽 — 슬라이드 코드를 옮기지 않는다).
   - 구조·흐름은 `diagram`(mermaid). 헷갈리는 곳은 `pitfalls`. 챕터마다 `check` 문제 1~3개(답 포함).
   - 국내 강의·비기술 강의(포트폴리오·커리어)도 같다 — 식·코드 대신 사례·체크리스트로 채운다.
   - **모든 노트는 초등학생도 따라올 눈높이로(2026-11-22, 사용자 요청 "초등학생도 이해할 수 있을 정도로 세세하게")** —
     중급·심화 강의도 같다. 어려운 내용을 빼는 게 아니라 **계단을 더 잘게** 놓는다.
     · 챕터 `explain` 첫 문단은 일상 비유(과자 나누기·줄 서기·택배·레고처럼 초등학생이 겪어 본 것)로 시작한다.
     · 전문 용어는 처음 나올 때 바로 괄호로 쉬운 말 풀이 — "경사 하강법(언덕을 한 걸음씩 내려가며 가장 낮은 곳을 찾는 방법)".
       `concepts` 에도 그 쉬운 풀이를 그대로 싣는다.
     · 한 문장에 새 개념 하나. 문장은 짧게. "당연히·자명하게·간단히" 로 건너뛰지 않는다 — 강의가 건너뛴 단계는 노트가 채운다.
     · 식은 먼저 말로("점수 = 무게 × 개수를 다 더한 것"), 그다음 기호, 그다음 작은 숫자(1·2·3)로 직접 계산해 보인다.
     · 챕터 끝 `points` 는 "한 줄로 말하면" 으로 읽히게, `check` 는 비유로도 답할 수 있는 쉬운 문제 1개를 꼭 넣는다.
     · 실습 강의(포토샵·피그마·코딩)는 클릭 하나까지 — 메뉴 경로·단축키·설정값을 번호 순서로.
     · "왜 이걸 배우나"를 노트 첫 `summary` 문단에 먼저 말한다. `level` 은 강의가 아니라 노트를 읽을 사람 기준으로 매긴다.
   - **짧은 영상(20분 미만)** 은 챕터 3~6개면 된다(분당 본문·챕터 600자 기준은 그대로).
   - 트랙별 topic: 코딩테스트 `coding-test` · 백엔드 `backend` · 프론트엔드 `frontend` · 디자인 `design` ·
     상세페이지·포토샵 `detail-page` · 토익 `toeic` (AI 는 기존 topic).
   - 실습 강의(포토샵·피그마·코딩)는 `example` 에 "따라 하기 순서"(메뉴 경로·단축키·설정값)를, `pitfalls` 에 초보가
     막히는 곳을 적는다. 코딩테스트는 `code` 에 직접 쓴 풀이와 시간 복잡도를.
   - **토익**: 기출·교재(ETS·해커스) 문제와 지문을 옮기지 않는다 — 풀이 방법·문법 규칙을 우리 말로 정리하고 예문은
     직접 만든다. `check` 도 직접 만든 문제로.
   - 요약은 **우리 말로 다시 쓴다.** 대본 문장을 옮기지 않는다(validate 가 긴 영어 덩어리를 막는다).
     용어·수식·짧은 고유명사만 원문 그대로.
   - 챕터는 8~15개, `start` 는 그 이야기가 시작되는 초(원본 영상의 그 자리로 링크된다).
   - `trends` 는 강의가 말한 업계 흐름이다. 강사의 의견이면 "강사 의견" 이라고 적는다.
   - `study` 는 "이 강의를 듣고 무엇을 어떤 순서로 공부하나" — 선수 지식·단계·손으로 할 과제·
     공식 자료(과목 홈페이지·논문·공식 문서) 링크.
   - `tags`·`jobs.skills` 는 공고 `tech_stack` 표기(PyTorch, Python, CUDA, Kubernetes …)에 맞춘다.
5. 검증: `python lecture-engine/validate.py` — 통과하면 `index.json` 이 다시 구워진다.
6. 기록: `state/LOG.md` 에 한 줄(날짜 · id · 제목 · 챕터 수). 커밋:
   `git add jd-viewer/public/lectures lecture-engine/state` → `feat(lectures): <과목> <제목> 노트`.
   푸시는 하지 않는다. 재료 폴더(`var/lectures/<id>`)는 커밋하지 않는다.
7. 정리(**빼먹지 않는다**): `python lecture-engine/clean.py --apply` — 먼저 노트를 DB(viewer_doc)에 저장하고
   (store.ingest.docs 동기화), 커밋되고 DB 에 들어간 강의의 장면 이미지·자막 원본·영상을 지운다(대본·메타만 남긴다).
   조건이 하나라도 안 맞으면 남긴다. 출력의 '지움 <id>' 를 보고에 적는다.

## 하지 않는 것
- 원본 영상·장면 이미지·대본을 공개 폴더에 두지 않는다 — 공개되는 건 노트뿐이고 원본은 링크한다.
- 유료 강의(인프런 유료 등)의 본문을 받지 않는다. 공개된 소개·커리큘럼 페이지만 쓴다.
- 봇 차단·로그인을 우회하지 않는다.
