**모바일 유닛 소개가 앱의 정체를 밝혔다** — `**360도 카메라, 드론 등 다양한 외부 기기를
제어**하여 디지털 트윈 솔루션을 활용할 수 있게 돕고`. **화면을 그리는 앱이 아니라 장비를
조종하고 큰 파일을 받아 오는 앱**이다. `company.signals` 에 넣었고, 골격 단계의
`현장 모바일 앱` 도메인 추론이 **본문으로 확인됐다**(그때는 BLE 한 줄로 짐작한 것이었다).

**이 공고에서 잡은 축**
- **BLE 로 찾아 연결하고 WiFi 로 사진을 받아 온다** — 그러면 **폰이 카메라 WiFi 에 붙는
  동안 인터넷이 끊긴다.** 라이브러리 문제가 아니라 **상태 기계 설계 문제**로 세웠다.
- **자격요건이 두 층인 이유**(Dart 3년 + 네이티브 1년) — **기기 제어는 결국 플랫폼 API** 다.
  drill 을 **양쪽을 다 채운 플러그인 만들기**로.
- **현장은 인터넷이 없다** — 오프라인 우선. 진짜 어려움은 저장이 아니라 **다시 만났을 때**
  (충돌·이어받기·중복·용량).
- **`Isolate` 이 우대사항에 콕 집혀 있다** — **360도 사진 한 장이 수십 MB**. 화면이 얼지 않게.
- **`Geo-referencing` 이 지도 항목 괄호 안에 있다** — **실내는 GPS 가 안 잡히니**
  도면 좌표와 실제 좌표를 잇는 문제가 남는다(프론트엔드 브리핑의 좌표계 문제가 여기도 온다).
- **모바일 장애는 재현이 안 된다** — 웹과 다른 점은 **고쳐도 심사와 업데이트를 기다린다**는
  것. 그래서 **원격으로 끌 수 있게 만들어 두는 것**이 곧 대응 속도다.
- **`melos` 를 이름까지 적었다** → 패키지가 여럿이고 **경계를 그을 사람**을 찾는다.
- **`온디바이스 LLM`** — 오프라인 현장 + AI 제품이라는 두 조건이 만나는 자리(`nice`).

**발견 — 이 공고만 AI 도구 요구의 강도가 낮다.** 다른 개발 공고는 전부 **자격요건**인데
Flutter 만 **우대사항**이다. **모바일 유닛의 강도가 낮은 것인지 공고를 덜 고친 것인지
확인하지 못해** `open_questions` 에 남기고 edge 에 질문으로 넣었다.

## 자료 접근 지도

어느 출처가 어떻게 읽히는지. 같은 벽을 두 번 들이받지 않으려고 적는다.

| 출처 | 읽는 법 | 메모 |
|---|---|---|
| 원티드 공고 | 크롤 데이터(`all_jobs_enriched.json`)에 본문이 통째로 있다 | 웹 접근 불필요. `full_jd` 까지 있다 |
| 사람인·잡코리아 공고 | 같음 | 본문이 짧게 잘린 건이 섞여 있다 |
| 회사 홈페이지·채용페이지 | WebFetch | `company.business` 의 1차 자료. 글로우업리즈는 `/aboutus` 에 경영진까지 있었다 |
| 언론 기사 | WebFetch | 매출·영업이익과 **대표 발언 직접 인용**이 여기 있다. `people` 의 유일한 근거가 되는 일이 많다 |
| 사람인 기업정보 | WebFetch | **사원수(국민연금)는 페이지에 있지만 평균연봉은 없다.** 별도 페이지로 나뉘어 있어 확인 실패 |
| 크레딧잡·잡플래닛 등 집계 | WebSearch 로 수치만 | **전 직군 평균**이다. 서비스마다 값이 다르다(글로우업리즈: 2,747 / 2,816 / 3,455만원) |

## 배운 것

- 연봉은 밴드로만 쓴다. 점 하나로 쓰면 그 숫자가 어디서 왔는지 다음 사이클이 못 되짚는다.
- **집계 서비스 수치는 페이지에서 직접 확인되지 않으면 `inferred` 로 내린다.** 검색 요약에만
  뜨는 숫자를 `confirmed` 로 올리면 근거 링크를 눌렀을 때 그 숫자가 없다.
- `study[].quote` 는 공고 원문 그대로여야 한다. 다듬으면 뷰어 하이라이트가 조용히 사라지고,
  조용한 실패는 아무도 못 알아챈다. `validate.py` 가 이걸 검사한다.
- **공고 본문의 회사 소개는 홍보문이라 언론 수치와 어긋난다.** 글로우업리즈 공고는 2024년
  매출 188억·영업이익 37억, 기사는 184억·32억이었다. 어긋나면 지우지 말고 `open_questions` 에
  둘 다 적는다.
- **`## 대기` 같은 머리말을 파이썬 `str.index` 로 찾아 자르지 않는다.** QUEUE.md 는
  본문에서 `` `## 대기` `` 를 인용하고 있어서 `index('## 대기')` 가 **머리말에 먼저
  걸린다.** 이번에 그렇게 잘라 헤딩이 통째로 날아갔고 `--gaps` 가 대기열 0곳으로
  읽었다. 섹션을 갈아 끼울 때는 줄 단위로 `^## 대기` 를 찾거나 표 행만 갈아 끼운다.
- **초기 스타트업은 집계 자체가 서지 않는다.** 딥오토는 설립 3년차·임직원 10~30명이라
  연봉 집계가 원티드 하나뿐이었고, 임직원 수도 자료마다 9/18/29명으로 갈렸다.
  이럴 때는 **전 직군 평균 밴드를 억지로 만들지 말고 시장 밴드 하나만 남기고**,
  집계가 없다는 사실 자체를 `note` 에 적는다(점 하나로 쓰지 않는 규칙과 충돌하지 않는다).
- **공고 수는 지원 가능한 자리 수가 아니다.** 넛지헬스케어는 모집중 39건인데 경력직
  개발 공고가 **하나**뿐이었다 — 나머지는 병역특례(산업기능요원)와 채용전환형 인턴이
  같은 직무로 사이트마다 중복 게시된 것이다. `--gaps` 의 후보 목록은 공고 수로만
  줄 세우므로, **QUEUE 에 올리기 전에 경력 요건 분포를 먼저 세어 본다.**
  ```
  python3 -c "
  import json,collections
  jobs=json.load(open('jd-viewer/public/all_jobs_enriched.json'))
  c=collections.Counter(j['career'] for j in jobs
      if '<회사명>' in j['company'] and j.get('status')!='closed')
  print(c.most_common())"
  ```
- **병역특례·인턴 비중이 큰 회사는 전 직군 평균 연봉이 아래로 눌린다.** 집계 숫자를
  그대로 읽지 말고 그 사실을 `salary.note` 에 적는다.
- **같은 회사가 같은 주제로 여러 자리를 여는 경우, 차이가 곧 브리핑의 값이다.**
  미리캔버스는 AI 자리를 최소 둘 열어 뒀다 — `AI Agent Engineer (Platform)`(3~6년)은
  에이전트를 만들 판(SDK·게이트웨이·레지스트리)을 짓고, `Node.js 개발자 (AI Agent)`(5~7년)는
  **합성팀**에서 AI팀의 R&D 결과물을 기존 파이프라인에 태우고 비결정성을 운영으로
  흡수한다. verdict 첫 줄에 **어느 쪽인지와 왜 다른지**를 밝히면 지원자가 고를 수 있다.
- **같은 회사의 비슷한 공고를 복사하지 않는다.** 미리디 프론트엔드 공고 둘은 제목이
  거의 같지만 완전히 다른 자리였다 — 에디터 쪽은 자격요건이 브라우저 API·React·CSS 인데,
  프로덕트 쪽은 **자격요건에 기술 스택이 한 줄도 없고** 전부 태도와 AI 도구 활용이다.
  공고 본문에 서로의 채용 링크를 걸어 두고 구분까지 해 준다. **먼저 두 본문을 나란히
  읽고 다른 축을 찾은 뒤에 쓴다** — 겹쳐 쓰면 브리핑 두 개가 같은 말을 하게 된다.
- **⚠️ 인용하는 공고 URL 을 지어내지 않는다.** 이번 사이클에서 도메인 근거로 원티드
  URL 두 개를 확인 없이 적었다가 대조해 고쳤다(`/wd/281148`·`/wd/354079` → 실재하지 않음).
  링크 하나가 틀리면 `confirmed` 등급 전체를 못 믿게 된다. 커밋 전에 아래로 확인한다.
  ```
  python3 -c "
  import json,re,pathlib
  jobs={j['url'] for j in json.load(open('jd-viewer/public/all_jobs_enriched.json'))}
  txt=pathlib.Path('jd-viewer/public/guide/companies/<slug>.json').read_text()
  for u in sorted(set(re.findall(r'https://www\.wanted\.co\.kr/wd/\d+',txt))):
      print('OK ' if u in jobs else '없음', u)"
  ```
  **`validate.py` 가 이걸 자동으로 잡아야 한다 — 별도 엔진 사이클로 넣는다.**
- **공고가 이력서 쓰는 법을 직접 적어 두는 경우가 있다.** 메가존클라우드 Platform
  Engineer 공고는 우대사항 끝에 '이력서 및 실무 면접 준비 추천 사항' 네 줄을 붙여
  '문제 상황 → 기술적 해결책 → 성과' 형식과 'GitHub·데모·블로그 활용'을 명시했다.
  **이건 채점 기준을 미리 알려 준 것이므로 study 항목으로 뽑는다** — 기술 공부가
  아니라고 흘려보내면 공고에서 가장 값나가는 줄을 버리는 셈이다.
- **공고 본문이 얇으면 학습 항목도 적게 나온다. 그게 맞다.** 메가존클라우드 풀스택
  공고는 인용 가능한 줄이 6개뿐이었고 담당 업무는 `full_jd` 에만 있었다. 억지로 9개를
  만들려면 공고에 없는 말을 지어내야 한다 — **6개로 끝내고 verdict 에 "본문이 얇다"고
  적는 편이 낫다.**
- **한 공고에 두 직무가 묶인 채용이 흔하다** (메가존클라우드는 확인한 개발 공고 셋이
  전부 그랬다). 크롤러는 이걸 한 공고로 보므로 `career` 도 둘 중 낮은 쪽이 뜬다.
  **`verdict` 에 어느 직무를 잡았는지 반드시 밝히고**, `study` 는 그 직무 것만 뽑는다.
- **사람인 공고는 절 구분이 어긋나 있다.** 메가존클라우드 공고에서 `qualifications`
  필드는 담당업무 + 자격요건 + (묶인 다른 직무의) 자격요건을 다 담고 있었고,
  `preferences` 는 우대사항 + 다른 직무의 담당업무를 담고 있었다.
  **`from` 은 의미상의 절이 아니라 그 문장이 실제로 들어 있는 필드로 적는다** —
  뷰어가 절 단위로 하이라이트하므로, 의미로 적으면 하이라이트가 안 걸린다.
- **`--gaps` 의 확장 목록은 본문 유무를 보지 않는다.** 같은 채용이 잡코리아·사람인에
  중복으로 올라오면 본문이 빈 잡코리아 건이 목록 위에 뜰 수 있다. **URL 을 그대로 집지
  말고 같은 제목의 사람인 건이 있는지 먼저 확인한다.** (엔진 코드를 고칠 일이지만
  데이터 사이클에 코드 변경을 섞지 않는다 — 별도 사이클로.)
- **사람인·잡코리아 공고는 `main_tasks` 가 통째로 비어 있다.** 본문이 전부 `full_jd` 에만
  들어 있다. `validate.py` 의 quote 검사는 `main_tasks + qualifications + preferences` 만
  보므로, 이런 공고에서는 **`from: "task"` 인 학습 항목을 만들 수 없다** — 자격요건과
  우대사항에서만 인용한다. 뷰어의 `주요 업무` 칸도 비어 보이는 것이 정상이다.
  (메가존클라우드는 본문 있는 40건이 전부 사람인이었다.)
- **회사명 표기가 갈리는 곳이 있다.** `메가존클라우드(주)` 와 `메가존클라우드㈜` 는

**형제 공고 둘 중 본체는 본문이 두꺼운 쪽으로 잡는다.** 큐픽스 데브옵스 둘 중

챌린지), **거기서 조직도(백엔드 유닛 = 3개 Part)와 24/7 온콜 체계가 나왔다.**

공고 한 장에서 아키텍처가 읽힌다. **어긋남은 오류가 아니라 정보다.**

**형제 공고의 차이는 `우대→필수` 이동에서 가장 잘 드러난다.** 큐픽스 데브옵스 둘은

**형제 공고를 비교할 때 절 이름이 바뀐 항목부터 찾는다.**

**한 공고 안에서 두 방향이 부딪히면 그것이 가장 좋은 면접 질문이 된다.** 큐픽스 인프라
공고는 `AI-driven 전환` 과 `폐쇄망 온프레미스` 를 함께 담당 업무로 둔다 — **폐쇄망에서는
외부 LLM 을 못 쓴다.** 이런 모순은 공고에 답이 없으므로 **지어내지 말고 `open_questions` 에
남기고 edge 에 질문으로 넣는다.** 지원자가 그것을 알아봤다는 사실 자체가 신호가 된다.

**같은 단어가 공고마다 무게가 다르다 — `C++` 이 그 예다.** 큐픽스 프론트엔드 공고의
`C++` 은 뒤 문장(`복잡한 코드도 빠르게 분석, 적응`)이 말해 주듯 **읽는 힘**에 가까웠지만,
Vision 공고의 `C++/Python` 은 **실제로 짜야 하는 언어**다(도구가 전부 C++ 다). **같은 단어를
발견하면 그 공고의 다른 줄과 도메인으로 무게를 판정한다** — 회사 단위로 한 번 정해 두고
모든 공고에 복사하면 준비 방향이 틀어진다.

**같은 Part 에 공고가 셋 이상이면 겹침을 지도로 관리한다.** 큐픽스 Infrastructure Part
하나에 데브옵스 둘 + 데이터 엔지니어가 있고 담당 업무가 서로 물린다. 매번 "무엇을 이미
썼나"를 기억으로 판단하면 반드시 겹친다. **STATE 의 표에 `무엇을 하는 자리` 한 줄을 적어
두는 이유가 이것**이고, 새 공고를 쓸 때 **이미 쓴 축을 먼저 지우고 남는 것**으로 시작한다
(이번에는 웨어하우스 비용을 지우고 저장소 분담·규정·오케스트레이션이 남았다).

**개발 직군이 아닌 공고에서 회사 사실이 더 많이 나오기도 한다.** 큐픽스 보안 공고는
소속이 **관리본부**라 회사 소개가 달랐고, 거기서 **보유 인증 셋(ISO 27001·CSA STAR·SOC 2)**과
**해외 오피스·현지 직원**이라는 사실이 처음 나왔다. 개발 공고만 읽으면 **회사의 절반만
본다** — 회사 골격을 채울 때 **보안·운영·관리 직군 공고를 한 편은 읽는다.**

**골격 단계의 도메인 추론은 나중 공고가 확인해 준다.** 큐픽스 골격에서 `현장 모바일 앱`
도메인을 **자격요건의 BLE 한 줄**만 보고 세웠는데, 열 번째 공고에서 팀 소개가
`360도 카메라, 드론 등 다양한 외부 기기를 제어` 라고 **직접 밝혔다.** 골격의 `inferred` 가
`confirmed` 로 바뀌는 순간이라, **공고를 다 쓴 뒤 골격을 한 번 되읽는 것**이 값을 한다
(닫기 전 점검 항목으로 넣을 만하다).

- `people` 은 대개 대표 한 명이다. 개발자가 쓴 공개 자료가 있는 회사는 드물고, 그럴 때
  **억지로 채우지 않는 것**이 규칙이다(PROMPT.md 2″단계).

**본문에 곧은 따옴표(") 를 쓰지 않는다.** SRE 사이클에서 `실험하는 것이다("가설" → 확인)`
처럼 큰따옴표를 썼다가 **JSON 이 통째로 깨졌다**(`Expecting ',' delimiter`). 다행히
append 전에 터져 파일은 안 망가졌다. 인용부호가 필요하면 `‘ ’` 나 백틱을 쓴다.

**같은 이름·다른 사이트라고 중복으로 단정하지 않는다.** 토스플레이스 `DevOps Engineer`
는 원티드와 사람인에 각각 있었고 **연차 표기까지 달랐지만**(6-15년 / 신입·경력),
본문을 읽으니 **아예 다른 자리**였다(운영 대 방향 수립). 사이트별 중복은 **본문을 읽고**
판단한다 — 제목과 연차만으로 지우면 자리를 통째로 놓친다.

**새 회사 골격은 `validate.py` 를 두 번 부딪히며 쓴다.** 인터엑스 첫 시도에서 오류가
8개 났다 — (1) `aliases` 에 `(주)…` 를 넣으면 안 된다(`norm_company` 가 이미 벗긴다.
못 벗기는 건 **`㈜` 뿐**이다), (2) `revenue[].domains` 는 **`company.domains` 의 이름과
글자까지 같아야** 한다, (3) **`signals[].confidence` 는 전부 `inferred`** 여야 한다
(PROMPT.md 3단계), (4) `company.domains` 의 모든 항목은 **어느 수익원엔가 걸려 있어야**
한다, (5) `aliases` 를 고치면 **index.json 도 같이** 고쳐야 한다.

**`full_jd` 는 회사 골격의 재료다.** 원티드 공고의 `full_jd` 앞부분에는 회사 소개가
통째로 들어 있다 — 인터엑스에서는 **시리즈B 180억·2026년 상장 목표·자기 규정
(`Industrial AI & DataSpace Partner`)·CEO 영상 링크**가 거기서 나왔다. 웹 검색으로
못 찾은 사실이 공고 본문에 있는 경우가 많으니, **새 회사 골격을 쓸 때 대표 공고 하나의
`full_jd` 를 먼저 읽는다.** (다만 `quote` 로는 못 쓴다 — validate 는 main_tasks·
qualifications·preferences 세 칸만 검사한다.)

**공고가 밋밋하면 회사에서 거꾸로 읽는다.** 인터엑스 프론트엔드 공고는 React·TS·REST·
성능 넉 줄이 전부라 그대로 쓰면 어느 회사 브리핑과도 구별이 안 된다. 대신 **회사가 파는
것에서 화면에 담길 내용을 유추해**(설비 시계열·검사 이미지·불량 통계) 어려움이 어디로
옮겨 가는지를 축으로 삼았다. **담당 업무가 짧은 공고일수록 이 방법이 필요하다.**

**공고 본문의 칸이 밀려 있을 수 있다.** 인터엑스 `[전문연구요원] Frontend`(344280)는
자격요건 칸에 우대사항 문장이 들어가 있고 우대사항 칸에는 직무와 무관한 조건이 있다.
**크롤 오류가 아니라 회사가 틀을 재사용한 것으로 보인다.** 이런 공고는 억지로 쓰지 말고
`open_questions` 에 불일치를 적어 두고 뒤로 미룬다.

**본문이 겹치는 형제 공고는 "차이에만 답하는 브리핑"으로 쓴다.** 인터엑스 `[울산]
백엔드`(342471)는 서울(328449)과 담당 업무·필요스택·자격요건·우대사항이 **글자까지**
같았다. 커넥트웨이브에서 쓰던 방식(겹침을 밝히고 다른 줄로만 축 세우기)을 한 단계 더
밀어, **학습 항목 하나를 아예 "다른 브리핑으로 가라"는 포인터로 썼다.** 겹치는 내용을
다시 쓰면 독자가 두 번 읽고, 나중에 한쪽만 고치면 두 브리핑이 어긋난다.

**사람인 공고는 연차 표기를 믿지 않는다.** 목록의 `신입·경력` 은 본문과 자주 어긋난다 —
인터엑스 `AI Infra · System Engineer` 는 표기가 `신입·경력` 인데 본문 필수가 **3년 이상**
이었고, 토스플레이스 `DevOps` 도 같았다. **본문의 필수 요건 줄을 근거로 삼는다.**
덧붙여 **사람인 크롤은 칸 배치가 원티드와 다르다** — 담당 업무와 필수 역량이 둘 다
`main_tasks` 에 들어가고 `qualifications` 가 비는 경우가 있다. `quote` 를 고를 때
세 칸을 다 훑는다.

**제목만 보고 공고를 판단하지 않는다.** 인터엑스에서 본문 불일치를 두 번 만났다 —
`[전문연구요원] Frontend`(344280)는 자격요건 칸에 우대사항이 들어가 있었고, 사람인
`생산 시뮬레이션 시스템 개발` 은 **본문이 통째로 `AI Infra · System Engineer` 였다.**
회사가 공고 틀을 재사용하며 생긴 것으로 보인다. **제목으로 중복·성격을 판단하지 말고
본문 세 칸을 읽는다.** 그리고 불일치를 발견하면 억지로 쓰지 말고 `open_questions` 에 남긴다.

**공고를 쓰기 전에 `status` 를 확인한다.** 인터엑스 `[전문연구요원] Frontend`(344280)를
다 쓰고 나서야 `validate.py` 경고로 **이미 마감된 공고**임을 알았다. 마감이어도 지우지
않고 `closed: true` 를 달아 남기는 것이 맞다(이 회사가 어떤 사람을 찾는지 보여 주고,
같은 틀이 다시 열린다) — 다만 **verdict 첫 문장에서 마감 사실을 밝히고 지금 지원할 수
있는 형제 공고를 가리켜야** 한다. 미리 알았으면 글의 방향을 처음부터 그렇게 잡았을 것이다.

**평균연봉이 플랫폼마다 다르면 범위로 적는다.** 인터엑스는 원티드 4,889 / 캐치 4,614 /
잡플래닛 4,168 / 사람인 6,365 로 **2,200만원 가까이 벌어졌다.** 하나를 고르면 그 순간
근거 없는 숫자가 되므로, **범위 + `inferred` + 왜 벌어지는지 설명**으로 적는 편이 맞다.
와탭랩스에서도 두 곳이 500만원 벌어졌던 적이 있다 — **직군이 넓고 근무지가 흩어진 회사일수록
평균 하나는 개발 직군 값을 말해 주지 못한다.**

**같은 자리가 제도로 갈려 있으면 한 편으로 묶고 성격을 바꾼다.** 페이타랩은 개발 직군
여섯을 **일반·병역특례 짝**으로 열었고 **본문이 글자까지 같았다.** 여섯 번 다시 쓰는 대신
**대표 공고 하나**에 묶고, 그 브리핑을 **기술 준비가 아니라 제도 판단**(자격 확인·복무
기간 설계·면접에서 물을 것)으로 채웠다. 직무 준비는 일반 공고 브리핑을 가리킨다.
**연차대·근무지 변형**(데이터·QA·Windows·iOS)도 같은 원칙으로 본체 하나만 쓴다.

**회사 블로그 주소는 리다이렉트를 따라간다.** 페이타랩 공고가 링크한
`blog.paytalab.com` 은 **301 로 `paytalab.teamblog.io` 로 옮겨져** 있었고, 원래 주소로는
본문이 안 읽혔다. 옮겨진 곳에서 **서명된 글 두 편**을 찾아 `people` 을 채웠다.
**`people` 이 비었다고 결론 내리기 전에 리다이렉트 한 번은 따라가 본다.**

**후보 조사는 `--gaps` 목록을 다시 정렬해서 쓴다.** 그 목록은 **공고 수로만** 줄 세운
것이라 상위가 늘 대기업·AI 튜터 채용으로 채워진다. 대신 **본문 있는 공고만 남기고**
회사별로 **신입 표기 수 · 비수도권 수 · 프론트엔드 제목 수**를 세어 **브리핑이 약한 쪽에
가중치**를 주면 전혀 다른 목록이 나온다(이번에 레브잇·큐픽스·플라잎이 그렇게 올라왔다).
그리고 **미룸 표를 반드시 다시 읽는다** — 사유가 틀렸을 수 있고(플라잎), 다음 순서를
적어 둔 경우도 있다(비바리퍼블리카).

**`all_jobs_enriched.json` 은 크롤이 쓰는 중일 수 있다.** 읽다가
`JSONDecodeError: Expecting value: line 1 column 1` 이 나면 파일이 깨진 것이 아니라
**auto_crawl 이 갱신 중**인 것이다(파일 크기가 커지는 중이었다). **20초쯤 기다렸다 다시
읽으면 된다.** `validate.py` 도 같은 이유로 실패할 수 있으니, 실패하면 파일을 고치지 말고
**한 번 더 돌려 본다.**

**크롤이 갱신되면 이미 쓴 공고가 마감될 수 있다.** 이번에 미리디 공고 하나가 그렇게
닫혔고 `validate.py` 경고가 잡아 줬다. **매 사이클 `경고 N` 을 확인하는 이유가 이것**이고,
경고가 뜨면 확장 사이클 사이에 **보수 사이클을 한 번 끼운다.** 처리 방법은 정해져 있다 —
`closed: true` 를 달고 **verdict 첫 문단에 마감 사실과 대안 공고**를 밝힌다.

**컨퍼런스 세션 페이지는 `people` 의 좋은 재료다.** 토스플레이스에서는 소속 확인이 안 돼
빈 배열로 닫았는데, 본체(비바리퍼블리카)는 **SLASH 세션 페이지에 발표자 실명과 직무가
적혀 있어** 두 사람을 바로 채울 수 있었다. **회사 블로그에 서명이 없으면 컨퍼런스 세션을
본다** — 발표는 그 자체가 `public_work` 이고, 세션 소개가 **무엇을 다뤘는지**까지 알려 준다.

**계열사가 여럿인 회사는 `salary` 를 법인별로 나눠 적는다.** 비바리퍼블리카는 본체
평균(5,997~14,717)과 토스인슈어런스 평균(5,338~7,508)이 **두 배 가까이** 달랐다. 한 줄로
섞으면 어느 쪽 지원자에게도 틀린 숫자가 된다. **공고 제목의 대괄호로 법인이 갈리는 회사**는
밴드도 그렇게 갈라 적고, `role` 에 법인 이름을 넣는다.

## 재시도 안 함

**인터엑스 소속으로 서명된 공개 결과물** — 두 번 찾았다. 회사 기술 블로그가 없고,
`INTERX Summit 2025` 기조연설(정하일 CTO)은 **행사 소식 기사만 있고 발표 자료·영상
링크를 못 찾았다.** 대표(박정윤) 인터뷰 기사는 여럿이지만 `public_work` 가 아니다.
**Summit 자료가 공개되기 전에는 다시 찾지 않는다.**

**토스플레이스 소속으로 서명된 공개 글·발표** — 두 번 찾았다. toss.tech 는 대부분
비바리퍼블리카·토스뱅크 소속이고, 회사 채용 페이지의 「토스플레이스 리더십 인터뷰」와
「토스플레이스에서 서버 개발자로 일하기」는 **본문이 스크립트로 그려져 정적 요청으로는
제목과 메뉴만 나온다.** SLASH 에 토스플레이스 세션이 올라오기 전에는 다시 찾지 않는다.
