# 책 데이터 형식

`/wiki` 가 읽는다. 화면은 `src/components/BookView.tsx`, 타입은 `src/lib/useBook.ts` 가 단일 소스다.
**색인 대상이 아니다** — 혼자 읽으려고 쓰는 책이라 `noindex` 를 걸고 sitemap·prerender 에서 뺐다.

```
book/
  index.json                  서가. 책 목록과 진행률
  <bookId>/
    toc.json                  한 권의 차례 전체 + 머리말·읽는 법·실습 환경
    pages/<pageId>.json       절 하나의 본문
```

파일을 셋으로 쪼갠 이유: 차례는 사이드바가 늘 들고 있어야 하고, 본문은 열어 본 절만
받으면 된다(한 절이 20~40KB 다).

## 주소

`/wiki` 서가 · `/wiki/<bookId>` 표지+차례 · `/wiki/<bookId>/<pageId>` 본문.
`pageId` 는 차례 번호(`4.1`)가 아니라 슬러그(`persistence-context-1`)다 — 순서가
바뀌어도 주소가 안 바뀌게.

## 본문 블록

본문은 마크다운 한 덩어리가 아니라 `blocks` 배열이다. 한 덩어리로 두면 "이 코드가
만들어 내는 SQL"·"이건 함정이다"·"면접에서는 이렇게 묻는다"가 전부 같은 회색 문단으로
흘러서, 훑을 때 걸려야 하는 자리가 안 걸린다.

| type | 쓰는 자리 |
|---|---|
| `prose` | 산문. 마크다운(목록·인용·표·펜스 코드 다 됨) |
| `heading` | 절 안의 소제목 |
| `code` | 코드. `bad: true` 면 '이렇게 하면 안 된다' 로 그린다 |
| `sql` | **위 코드가 실제로 만들어 내는 것.** 절의 마지막 블록이다 — `lang` 으로 무엇인지 정한다 |
| `callout` | `tone`: `why` `tip` `note` `warn` `trap` `interview` |
| `table` | 비교표. 셀은 인라인 마크다운(`**`, 백틱) 가능 |
| `compare` | 좌우 대조. 한쪽에 `bad: true` 를 주면 ✓/✗ 가 붙고, 안 주면 중립 비교로 그린다 |
| `steps` | 번호가 의미 있는 순서 |
| `figure` | ASCII 그림 |
| `terms` | 본문 중간의 낱말 상자 |

`sql` 블록의 `lang` 은 책마다 다르다 — 기본값 `sql`(JPA), `text`(실행 결과·로그),
`http`(오간 HTTP). 이름이 `sql` 로 남은 것은 56절이 이미 그 이름으로 쓰여 있어서다.

절 끝에는 `recap` / `drills` / `quiz` / `terms` / `sources` 가 온다.

## ASCII 그림 규칙 (중요)

**상자 테두리 왼쪽에는 한글을 두지 않는다.** 한글 글리프는 등폭 폰트에서도 정확히
2칸이 아니라서, 테두리 앞에 한글이 있으면 그 줄만 밀려서 그림이 깨진다.
상자 안은 ASCII 로만 채우고 한글 설명은 줄 끝(테두리 바깥 오른쪽)에 붙인다.
그러면 폭이 어긋나도 밀리는 건 설명 글자뿐이다.

```
        ┌────────────────────────┐
        │  EntityManagerFactory  │   ← 딱 1개. 만드는 데 몇 초 걸린다.
        └────────────────────────┘
```

마크다운 표식(`**`)은 `figure` 안에서 글자 그대로 나온다. 쓰지 않는다.

## 상태

`toc.json` 의 절마다 `status`: `done`(완성) / `draft`(초고) / `todo`(아직 안 씀).
`todo` 는 차례에 회색으로 보이되 링크가 아니고, 이전/다음도 건너뛴다 — 빈 페이지로
가는 '다음' 버튼은 고장으로 보이기 때문이다.
`index.json` 의 `written` 은 `todo` 가 아닌 절의 개수와 맞춰 준다.

## 읽은 자리

브라우저 `localStorage` 에만 남는다(`jd-book:<bookId>:read` / `:last`).
나만 보는 책이라 서버에 둘 이유가 없고, 접근이 막힌 환경에서는 없는 대로 돈다.

## 집필 사이클

**한 사이클 = 2~3절 = 한 커밋.** 스무 권이 이 리듬으로 쓰였다. 한 번에 한 장을
통째로 쓰면 뒤쪽 절이 앞쪽의 요약이 되고, 한 절만 쓰면 절 사이의 이음새가 안 보인다.

### 무엇을 쓸지는 고르지 않는다

파일이 정한다. 감으로 고르면 쓰기 쉬운 절만 골라 쓰게 되고 어려운 장이 영영 안 열린다.

```bash
python3 jd-viewer/scripts/book_check.py --check
```

출력에서 `✓` 가 안 붙은 첫 장, 그 장의 첫 `todo` 절부터 차례대로. **장을 가로지르지
않는다** — 한 커밋이 두 장에 걸치면 커밋 제목이 그 장을 말할 수 없게 된다.

`index.json` 에 `status: writing` 인 책이 집필 대상이다. 그런 책이 없으면 새 책을
여는 사이클이고, 그때는 `toc.json` 을 먼저 통째로 짠다(절 제목·`summary`·`minutes`
까지). 차례 없이 본문부터 쓰면 책이 아니라 글 모음이 된다.

### 매 절은 눈으로 확인할 수 있는 것으로 끝난다

**그 '것' 이 책마다 다르고, `index.json` 의 `blurb` 에 적혀 있다.** JPA 는 실제로
나가는 SQL, MVC 는 오간 HTTP, 도커는 친 명령과 그 출력, JVM 튜닝은 GC 로그와 힙
스냅숏이다. 그 블록(`sql` 타입, `lang` 으로 무엇인지 정한다)이 절의 마지막이다.

**막힌 것도 같이 싣는다.** 에러 응답·CrashLoopBackOff·빨간 막대는 빼는 게 아니라
주제다. 잘 되는 것만 실으면 읽는 사람이 막혔을 때 이 책이 아무 말도 못 한다.

**지어낸 출력을 싣지 않는다.** 로그와 SQL 은 실제로 돌려서 얻은 것이다. 못 돌렸으면
그 절은 아직 안 쓴 것이다 — `todo` 로 두고 다음 절로 가지 않는다.

### 상태는 손으로 고치지 않는다

`toc.json` 의 `status` 와 `index.json` 의 `written`·`sections`·`chapters` 는
**`book_check.py` 가 파일 목록에서 다시 계산한다.** 손으로 고치면 반드시 어긋나고,
어긋나면 차례는 '예정' 인데 본문이 있거나 '다음' 버튼이 빈 페이지로 간다.

```bash
python3 jd-viewer/scripts/book_check.py      # 검사 + 동기화
```

**문제가 하나라도 남으면 커밋하지 않는다.** 이 검사기는 ASCII 그림 규칙(위 「ASCII
그림 규칙」)도 같이 본다.

손으로 두는 것은 둘뿐이다 — `index.json` 의 `status`(마지막 절을 쓴 사이클에서
`writing` → `done`)와 `updated_at`.

### 커밋

```
docs(book): <책 약칭> <n>장 — <그 절들이 다루는 것>
docs(book): <책 약칭> <n>장을 닫는다 — <그 장이 남긴 것>     # 장의 마지막 절일 때
docs(book): 서가에 <제목> 을 올리고 1장을 연다                # 새 책
```

책 데이터만 담는다. 뷰어 코드 변경은 섞지 않는다 — `git add -A` 를 쓰지 않고 파일을
지정한다. `git push` 는 사용자가 명시적으로 말할 때만 한다(CLAUDE.md).
