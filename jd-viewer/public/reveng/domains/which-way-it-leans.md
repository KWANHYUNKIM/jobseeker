# 무엇을 잃기로 정했는가 — 오차를 어느 쪽으로 몰았는가

> 비교 대상: Moniepoint `critical-path` · Doximity `cdc-overlap` · Yelp `partition-access` ·
> Target `split-shipments`·`repurchase-timing`
> 각 회사 페이지에서 `확인`으로 정리한 사실만 엮었다. 비교에서 나오는 해석은 **추정**으로 표시했다.
>
> 재 보고 무엇을 골랐는가는 비교 문서 `재 보고 나서 — 숫자가 그대로 답이 된 적이 없다` 에,
> **안 하기로 한** 결정들은 `안 하기로 한 것을 어떻게 적는가` 에 있다.
> 여기서는 **하기로 한 뒤 내준 것**, 그리고 **그 오차가 어느 쪽으로 기울었는지**만 본다.
> (Yelp `partition-access` 와 Target `repurchase-timing` 은 앞 문서에도 나오는데, 저기서는
> *재 보고 무엇을 골랐나*였고 여기서는 *고르면서 오차를 어느 쪽으로 몰았나*다.)

완전성을 조금 내줬다는 이야기는 대개 **양**으로 전해진다 — 0.1% 만 잃는다, 9% 만 포기한다.
그런데 다섯 사례에서 실제로 중요한 것은 **얼마나**가 아니라 **어느 쪽으로**였다. **오차가
무작위로 흩어지지 않고 한 방향으로 기울게 설계돼 있다.**

가장 분명한 자리가 Doximity 다. CDC 초기 적재를 배치 스냅샷에서 넘겨받으면서 **겹침과 간극
중 무엇을 받을지**를 정면으로 골랐다 — 복원 지점 이후의 보존 이벤트를 다시 큐에 넣어, 이미
스냅샷에 든 것이 재생돼도 *"결국 수렴"* 하게 둔다. **겹친 것은 시간이 지우지만 빠진 것은
시간이 못 만든다**(이 문장은 이 사이트의 정리다).

## 무엇을 내주고 무엇을 샀는가

| | 내준 것 | 산 것 | 회사의 말 |
|---|---|---|---|
| Moniepoint `critical-path` | **완전성** — 신선도 창(*"시간이 아니라 분 단위"*) 밖의 이벤트를 버린다 | **신뢰** | *"약간의 완전성을 훨씬 큰 신뢰와 맞바꿨다"* |
| Doximity `cdc-overlap` | **중복 없음** — 같은 이벤트를 두 번 처리하는 구간이 생긴다 | **간극 없음** | 재생돼도 *"결국 수렴"* 한다 |
| Yelp `partition-access` | **정확성** — 서버 접근 로그는 *"누락되거나 늦게 오거나 중복될 수 있다"* | **비용**(버킷당 $0.25 정액) | *"며칠 넘게 늦게 오는 것은 0.001% 미만"* |
| Target `split-shipments` | **최적해** — 비용 격차의 **약 9%** | **계산 시간**(브루트포스의 약 8%) | *"약 91% 를 메우면서 … 약 8% 만 쓴다"* |
| Target `repurchase-timing` | **카탈로그의 꼬리** — 빈도 문턱 아래 품목이 모델에서 빠진다 | **지연**(70ms 미만) | *"잠재적 반복구매를 의도치 않게 빠뜨릴 위험이 있다"* |

## 기운 방향이 전부 '나중에 고칠 수 있는 쪽' 이다

**이게 다섯을 관통하는 것이다**(이 정리는 이 사이트의 것). 오차를 없앨 수 없으니 **되돌릴 수
있는 쪽으로 몰아 놓았다.**

| | 오차가 기우는 방향 | 그 방향이 안전한 이유 |
|---|---|---|
| Doximity | **중복 쪽** | 겹침은 **멱등으로 흡수된다** — 그래서 *"모든 적용이 멱등해야 한다"* 는 제약이 따라온다. 간극은 흡수할 방법이 없다 |
| Yelp | **'안 쓰인다' 쪽** | 놓친 접근이 '미사용' 으로 보이므로 **지우는 결정에는 위험하고 내리는 결정에는 안전하다.** 그래서 실제로 **내리는 쪽에** 쓴다 |
| Moniepoint | **버리는 쪽** | 늦은 이벤트를 처리하지 않는 대신 **DLQ 로 흔적을 남긴다** — *"DLQ 모니터링이 운영 모델의 일부"* 가 된다 |
| Target `split-shipments` | **주문 한 건 안쪽** | 남은 9% 는 그 주문의 배송비이고 **다음 주문에 누적되지 않는다**(이 관찰은 이 사이트의 것) |
| Target `repurchase-timing` | **추천 안 함 쪽** | 안 뜬 물건은 **사용자가 직접 찾을 수 있다.** 틀린 추천은 사용자가 되돌릴 방법이 없다(이 대비는 이 사이트의 해석) |

**Yelp 가 이 원리를 가장 멀리 밀고 갔다.** 부정확한 자를 쓰기로 한 데서 멈추지 않고, **그 자를
어디에 쓸 수 있는지까지 정했다.** 보존 창 밖의 데이터도 지우지 않는다 —
`Default Access Retention` 은 데이터를 **S3 에 그대로 두고** 읽으려면 *"명시적 절차"*(Terraform
PR 승인)를 거치게 한다. **삭제와 방치 사이에 마찰이라는 한 칸을 만든 것**이고, 그래서 판정이
틀려도 되돌릴 수 있다.

**반대로 Moniepoint 는 되돌릴 수 없는 쪽을 골랐다** — 버린 이벤트는 돌아오지 않는다. 대신
**그 값을 알고 낸다**: *"약간의 완전성을 훨씬 큰 신뢰와 맞바꿨다."* 여기서 산 것이 데이터가
아니라 **가용성**이기 때문이다 — 회사가 그 무게를 사람으로 환산해 적는다: *"0.1% 의 가용성
저하는 대시보드의 선 하나가 아니다. 통과하지 못한 수천 건의 거래이고, 그 순간 신뢰를 잃은
수천 명의 고객이다."*

## 내준 것이 세어지는가 — 대부분 안 세어진다

**다섯 중 내준 양을 실제로 아는 곳은 둘뿐이다.**

| | 내준 양을 아는가 |
|---|---|
| Yelp | ✅ **안다** — *"며칠 넘게 늦게 오는 것은 0.001% 미만"*. 다만 **9일 뒤**에 온 것도 있었다 |
| Target `split-shipments` | ✅ **안다** — 비용 격차의 **약 9%**. ⚠️ 다만 브루트포스 대비 **상대값**이고 절대 금액은 없다 |
| Moniepoint | ❌ **모른다** — 버린 이벤트가 전체의 몇 %인지 나오지 않는다. *"약간"* 이라는 말뿐이다 |
| Doximity | ❌ **모른다** — 겹침 구간이 얼마나 긴지, 수렴까지 몇 번 중복 처리되는지 나오지 않는다 |
| Target `repurchase-timing` | ❌ **모른다** — 빈도 문턱값도, 빠진 품목의 비율도, 놓친 반복구매 수도 공개되지 않는다 |

**세는 쪽과 못 세는 쪽에 차이가 있다.** Yelp 와 Target 의 분할은 **버린 것이 관측 가능한 자리**에
있다 — 늦게 온 로그는 도착하니까 세어지고, 브루트포스는 (느리지만) 돌려 볼 수 있으니 격차가
계산된다. **나머지 셋은 버린 것이 애초에 시스템에 안 들어온다** — 신선도 창 밖의 이벤트, 문턱
아래의 품목, 수렴해 사라진 중복은 세려면 따로 세는 장치를 만들어야 한다(이 구분은 이 사이트의 것).

## 회사가 그 대가를 스스로 적었는가

| | 대가를 적었는가 |
|---|---|
| Moniepoint | ✅ **한 문장으로 적었다** — *"약간의 완전성을 훨씬 큰 신뢰와 맞바꿨다."* 그리고 따라오는 부담(DLQ 모니터링, 매 이벤트의 나이 계산)까지 적는다 |
| Target `repurchase-timing` | ✅ **적었다** — *"덜 팔리는 품목을 빼서 모델을 줄이면 지연을 줄이는 데는 도움이 되지만 잠재적 반복구매를 의도치 않게 빠뜨릴 위험이 있다"* |
| Doximity | ✅ **적었다** — 미룬 병합이 *"읽기 증폭"* 을 낳고 *"나이와 양 임계값이 그 읽기 증폭을 통제"* 한다. 그리고 자동화가 못 만든 삭제는 *"건너뛴 캐스케이드 모니터링"* 으로 넘긴다 |
| Yelp | ⚠️ **절반만** — 찬 스토리지 클래스의 값(*"최소 보관 기간과 접근당 요금이 있어 예상보다 자주 접근하면 절감이 상쇄될 수 있다"*)은 적는데, **놓친 접근이 '안 쓰임' 쪽으로 기운다는 것은 이 사이트의 해석**이다 |
| Target `split-shipments` | ⚠️ **수치로만** — *"약 91%"* 를 적어 9% 를 남긴 것은 드러나지만, **그 9% 가 어떤 주문에서 크게 벌어지는지는 글에 없다** |

**Doximity 의 방식이 여기서 눈에 걸린다** — 자동화가 못 채운 구멍을 **사람이 지켜보는 일**로
바꿔 놓았다. 합성 삭제 이벤트를 못 만드는 경우(복합 기본키, 관계 컬럼 없음)를 그냥 두는 대신
*"건너뛴 캐스케이드 모니터링과 메타데이터 신선도가 운영 모델의 일부"* 라고 적는다.
**구멍을 없애지 못하면 구멍이 있다는 것을 운영에 등록한다**(이 정리는 이 사이트의 것).

## 이 사이트에 아직 없는 것

- **기운 방향이 틀렸던 사례가 없다.** 다섯 다 방향을 잘 골랐다는 서술로 끝난다. **'안 쓰인다'
  로 판정했는데 실제로 쓰이던 데이터, 버렸는데 필요했던 이벤트** 같은 이야기를 아직 못 찾았다
  (회사가 자기 블로그에 쓰는 글이라 당연할 수도 있다 — **추정**).
- **내준 양을 나중에 다시 잰 곳이 없다.** Yelp 의 0.001% 도 Target 의 9% 도 **처음 잰 값**이고,
  시간이 지나 그 비율이 변했는지는 어디에도 없다.
- **문턱값이 대부분 비공개다.** Moniepoint 의 신선도 창은 *"분 단위"* 까지만, Target 의 빈도
  문턱은 아예 없고, Doximity 의 *"나이나 양 임계값"* 도 값이 안 적혀 있다. **문턱이 곧 잃는
  양을 정하는데 그 숫자가 없다.**
- **되돌린 기록이 없다.** Yelp 는 `Default Access Retention` 으로 되돌릴 길을 만들어 두었는데,
  **실제로 그 승인 절차를 거쳐 옛 데이터를 다시 읽은 사례가 나오지 않는다.** 되돌릴 수 있게
  만든 것과 되돌려 본 것은 다른 이야기다.
