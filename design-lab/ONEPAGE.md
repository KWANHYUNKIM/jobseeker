# 공고 한 장 만들기 — 3단계

인스타 피드(1080×1350, 4:5)에 공고 **전문**을 한 장으로 올린다. 폰에서 확대해 읽는 걸
전제로 하니 내용을 자르지 않는다. 대신 **AI 가 만든 티**가 나면 안 된다 — 그래서 모양은
지어내지 않고 사람이 만든 레퍼런스(8780 의 `refs.json`)와 회사가 실제로 쓰는 UI 에서 가져온다.

```bash
cd design-lab
python -m poster.carousel <공고키> --one --frame label_sheet
# → out/<공고키>/label_sheet_ig_portrait.jpg
```

| 단계 | 하는 일 | 어디에 남나 |
|---|---|---|
| 1. 내용 가져오기 | 대시보드(5173 `/jobs/<공고키>`)에 보이는 전문을 그대로 | `state/jobs_index.json` 의 `full` |
| 2. 회사 조사 | **[BRAND_RESEARCH.md](BRAND_RESEARCH.md) 절차서대로.** 대표 물건(시그니처) 하나 → 보조 2개 → 실제 서체 → 공식 픽셀 색 → 원본 이미지 | `brands/<회사>.json` 의 `signature` · `points` · `ui` · `images` |
| 3. 틀 입히기 | 레퍼런스 틀(구조) 또는 **회사 전용 판**(포인트를 자리로 옮긴 것). 전용 판이 있으면 그게 본판이다 | `poster/templates/<틀>.html`, `--frame brand` |

> 2026-09-15 — 2단계는 네 번 바뀌었다(웹 색·글꼴 → 포인트 → 실제 서체·색·이미지 → **대표 물건 중심**).
> 경위와 지금 절차는 BRAND_RESEARCH.md. 회사 전용 판이 있으면 그게 본판이고, 아래 3단계의 레퍼런스 틀은 전용 판이 없는 회사용이다.

## 1단계 — 내용 가져오기

대시보드 상세 화면과 포스터는 같은 원본(`jd-viewer/public/all_jobs_enriched.json`)을 읽는다.
색인(`poster/jobsource.py`)이 한 장짜리 포스터용으로 불릿을 3~5개·68자에서 잘라 두기 때문에,
전문은 따로 `full` 에 담는다.

- `full.tasks` — 주요업무를 `1.` `2.` 소제목 단위로 묶은 것 `[{title, items}]`
- `full.qualifications` / `full.preferences` — 자르지 않은 줄 전부
- `full.benefits` — `· 리프레시 : 생일자 반차, …` → `{label, text}`

색인 필드가 바뀌면 `jobsource.SCHEMA` 를 올린다. 원본이 그대로여도 옛 색인을 다시 만든다.

**확인:** 브라우저로 상세 화면 텍스트를 읽어 `full` 과 줄 단위로 대조한다. 채용 전형처럼
상세 화면의 섹션에 없는 것(원문 `full_jd` 에만 있는 것)은 넣지 않는다.

## 2단계 — 회사가 추구하는 UI

사실(설립·제품·수치)이 아니라 **모양**을 가져오는 단계다. 스크린샷을 눈으로 보는 것에
더해, 페이지에서 `getComputedStyle` 로 h1/h2/h3/p/버튼의 글꼴·크기·굵기·자간·색을 뽑는다.
감으로 적은 색은 틀린다.

`brands/<회사>.json` 에 남기는 것:

```json
"ui": {
  "observed_at": "어디서 언제 봤나",
  "font": "...", "display": "sans | serif",
  "paper": "바탕", "ink": "제목", "text": "본문", "sub": "보조", "accent": "강조",
  "rules": ["색을 어디에만 쓰는지", "정보를 어떤 짝으로 보여 주는지", "..."]
}
```

`rules` 가 핵심이다. 색 코드보다 **그 색을 어디에 쓰는지**가 회사다움을 만든다.

## 3단계 — 틀 입히기 (AI 티 없애기)

`refs.json` 에서 "공고 전문을 한 장에 담은 사람의 작업"을 고른다. 고를 때 보는 것:
정보량이 우리 공고와 비슷한가 / 장식 없이 타이포와 정렬만으로 버티는가.

### AI 티로 판정해 뺀 것

첫 시안(`--frame onepage`)에 있던 것들. 하나하나는 무난한데 모이면 생성물처럼 보인다.

| 뺀 것 | 대신 |
|---|---|
| 제품을 흉내 낸 장식 SVG(디스크 그림) | 없음. 그림을 쓸 거면 회사가 준 진짜 사진 |
| 왼쪽 강조 막대가 붙은 수치 카드 3개 | 없음. 공고는 제품 광고가 아니다(detail-01 drop) |
| 자간 넓힌 영문 대문자 머리말 `OPEN POSITION` | 레퍼런스처럼 큰 `We are / Hiring.` 두 줄 |
| 색 사각 불릿 | 불릿 없음. 넘어간 줄만 들여 써서 항목 경계를 만든다 |
| 알약 칩, `#해시태그` | 꼬리의 `라벨 값` 한 줄 |
| 라벨마다 강조색 | 강조색은 딱 한 곳(제목 둘째 줄) |
| 작은 회색 출처 각주 | 없음 |

### 틀이 정하는 것 / 브랜드가 정하는 것

틀(`label_sheet.html`, hire-17 에서):
- 머리: 큰 영문 두 줄 + 국문 제목 한 줄 + 오른쪽 위 워드마크
- 본문: `라벨 – 값` 한 규칙. 값이 여러 줄이면 라벨 자리를 비우고, 넘어간 줄은 들여 쓴다
- 꼬리: 구분선 두 줄 사이에 경력·기술·마감·지원. **없는 값은 줄째로 안 그린다**(hire-17 의 '모집 인원 0 명' 반면교사)

브랜드(`brands/*.json` 의 `ui`):
- 글꼴, 바탕·제목·본문 색, 강조색이 들어갈 자리
- 브랜드가 없으면 레퍼런스 원형(크림 종이 + 검정 + 세리프 이탤릭)으로 그린다

### 배치는 스크립트가 고른다

캔버스는 4:5 로 고정하고, 스크립트가 (1단/2단 × 라벨 옆/라벨 위) 모든 경우를 이분 탐색으로
돌려 **본문 글자가 가장 커지는 배치**를 고른다. 18px 아래로 내려가면 CLI 가 경고한다.
