# 콘텐츠 계획 — @devjobseeker 게시물 100개를 만들고 나눠 올리는 절차

공고 판 한 장(BRAND_RESEARCH.md)과 카테고리 묶음(SOCIAL.md)은 이미 있다. 이 문서는 그 위에
**게시물 네 종류를 섞어 대량으로 만들고, 검수하고, 안전한 속도로 올리는 절차**를 적는다.
2026-09-30 에 처음 10개를 이 절차로 만들었다.

```
조사(1) → 고르기(2) → 찍기(3) → 검수(4) → 승인함 inbox/ → 올리기(5) → 원장 기록(6)
```

## 1. 조사에서 가져온 것 (2026-09-30)

채용 사이트 계정이 무엇을 올리는지 보고 형식만 빌렸다. 숫자·글은 빌리지 않는다.

| 계정 | 본 것 | 우리가 가져온 것 |
|---|---|---|
| 원티드 `@wantedjobs.kr` | 게시물마다 첫 장의 주인공 그림이 다르다(사진·차트·그라데이션). 질문형 훅("내 연봉 적정 수준은?") | 첫 장 주인공을 카테고리마다 다르게 — 브랜드색 타일·기술 집계 표·마감 타임라인 |
| 사람인 `@saramin_jobopen` | 채용관마다 색 테마, 참여 회사를 위에 늘어놓음, "매주 추천 공고 5" | 이번 주 묶음 표지 = 뽑는 회사들의 브랜드색 타일 |
| 점핏 `@jumpit.official` | `[점핏연구소]` 처럼 대괄호 시리즈 머리말, 단정형 훅 → 항목 5개 | 시리즈 머리말 `[데이터로 본 채용]` `[들어가려면]` `[회사 해부]`, 가이드는 항목 5개 |
| 캐치 `@catch.job` | 하이라이트 = 시리즈(신입공고·공채속보·기업분석), `#캐치설문` 수치 훅 | 하이라이트를 시리즈 이름과 같게 만든다(아래 7절) |
| 그룹바이 | 연봉 데이터를 슬라이드마다 축 하나로 쪼갠다 | 데이터 카드는 한 장에 축 하나 |

일반 규칙(조사 출처: Meta 개발자 문서, Buffer 2026, Social Media Today, adpicto 등):

- 규격 1080×1350(4:5). 캐러셀 첫 장 비율로 나머지가 잘린다 → **첫 장부터 4:5**.
- 7–10장이 좋다. API 캐러셀은 10장까지다.
- 첫 장 문구는 40자 이하. 캡션 첫 125자(더보기 전)에 키워드를 둔다.
- **해시태그는 게시물당 5개 상한**(2025 말부터). `publish/caption.py` 의 `IG_TAGS = 5`.
- 캐러셀 참여율이 단일 이미지·릴스보다 높고, 저장이 많다 → "저장해 두고" 로 끝낸다.

## 2. 네 종류와 재료

| 종류 | 시리즈 머리말 | 재료(로컬) | 만드는 명령 |
|---|---|---|---|
| 공고 묶음 | 표지 칩(이번 주 채용 / 직군별 / 기술별 / 규모별 / 신입 가능) | `state/jobs_index.json` 모집중 + 전용 판 있는 회사 | `python -m publish.cli approve-collection <kind> --value …` |
| 회사 해부 | 회사 해부 | 한 회사의 모집중 공고 + `brands/<회사>.json` 색 + 취업 브리핑 한 줄 | `approve-collection company --value 올리브영` |
| 데이터 인사이트 | `[데이터로 본 채용]` | `jobs_index.json`(기술·신입 비율), `jd-viewer/public/freelance.json`(외주 단가) | `python -m poster.series stack` / `rates` |
| 취업 가이드 | `[들어가려면]` | `jd-viewer/public/guide/companies/<slug>.json` 의 `postings[].study` | `python -m poster.series guide 쿠팡` |

지금 만들 수 있는 양(2026-09-30 기준, 원본 확인 전 수):

- 전용 판이 있는 모집중 공고 70건 / 16개사 — 올리브영 20, 컬리 9, 포티투닷 7, 쿠팡·토스플레이스 5 …
- 묶음은 같은 회사가 여러 카테고리에 겹친다. **승인하는 순서대로 앞 묶음에 실린 공고는 뒤 묶음에서 빠진다**
  (`publish/posted.py` 가 inbox·원장을 읽는다). 그래서 한 회사가 여러 게시물에 나와도 같은 공고는 한 번이다.
- 전용 판 공고가 떨어지면 `validate`/`collection gaps` 가 다음에 전용 판을 만들 회사를 알려 준다
  (BRAND_RESEARCH.md 절차). 기본 틀(`--allow-generic`)은 급할 때만.

## 3. 찍기 — 디자인이 겹치지 않게

**시리즈마다 색 하나, 틀은 하나.** 3칸 그리드에서 색이 번갈아도 한 계정으로 읽히게 한다.

| 시리즈 | 첫 장 주인공 | 바탕 / 강조 | 틀 |
|---|---|---|---|
| 이번 주 채용 | 회사 브랜드색 타일 8칸 | 종이 `#f4f1ea` | `collection_hook.html` `k-week` |
| 직군별(데이터 등) | 기술 집계 표 | 남색 `#0d1420` / 청록 `#3ee0c1` | `k-role` |
| 신입 가능 | 마감 날짜 세로 타임라인 | 민트 `#e9f6ee` / 초록 | `k-newgrad` |
| 회사 해부 | 회사 이름 크게 + 한 줄 소개 | **그 회사의 색**(`ui.accent`) | `k-company` |
| 데이터로 본 채용 | 큰 숫자 하나(%·만원) | 종이 `#f5f2ea` / 주황 `#ff5a1f` | `series.html` insight |
| 들어가려면 | 회사 이름 + "들어가려면" | 남색 `#102a43` / 노랑 `#ffc53d` | `series.html` guide |

둘째 장(차례)도 첫 장과 같은 색을 이어받는다(`collection_cover.html` 의 `k-*`). 셋째 장부터는 공고 판
(회사 전용 판 → 직군 틀 → 기본 틀 순으로 본문 16px 을 넘는 첫 틀).

### 캡션 — 목록만 두지 않는다

회사가 나오는 게시물(회사 해부·들어가려면)은 캡션에 **그 회사에 대한 쓸모 있는 정보**를 붙인다
(`poster/series.py` 의 `company_info`, 회사 해부는 `publish/caption.py` 가 자동으로 부른다).

```
▪ 무슨 회사          브리핑 company.business 앞 세 문장
▪ 규모              scale 중 confirmed 만 셋(매출·영업이익·매장 수 …)
▪ 어떻게 돈을 버나    revenue 이름 셋
▪ 채용에서 읽히는 것   signals 둘 — inferred 면 "(추정)" 을 붙인다
▪ 개발자가 알아두면 좋은 것   domains[].what_to_know 넷
▪ 연봉(확인된 것)     salary.bands 중 confirmed 만 — 없으면 줄을 빼고 지어내지 않는다
※ 회사 정보는 공시·기사·공고를 모아 정리했습니다. 추정은 (추정)으로 표시.
```

재료는 `jd-viewer/public/guide/companies/<slug>.json`(guide-engine, 출처 필수). 2,200자를 넘으면 뒤 블록부터 뺀다.

### 릴스 — 같은 판을 9:16 영상으로

`python -m poster.reel inbox/<id>` → `inbox/<id>/reel.mp4`. 판을 다시 그리지 않고 4:5 판을 9:16 캔버스
가운데 놓는다. 위 띠에 그 게시물의 제목과 진행 막대, 아래 띠에 "저장해 두고 보세요 / 전문은 게시물에서".
띠 색은 시리즈 색(회사 해부는 그 회사의 색). 소리는 우리가 만든 `assets/audio/bed_calm.wav`
(인스타 음원 라이브러리는 API·웹 업로드로 못 쓴다).

| 종류 | 한 장 | 싣는 장 |
|---|---|---|
| 데이터 | 3.0초 | 전부(5장 ≈ 15초) |
| 들어가려면 | 3.2초 | 앞 8장 |
| 회사 해부·묶음 | 2.2초 | 표지·차례 + 판 6장(공고 전문은 영상에서 못 읽는다 → "전문은 게시물에서") |

같은 내용을 캐러셀과 릴스로 **같은 날** 올리면 중복으로 보인다. 릴스는 캐러셀을 올린 뒤 며칠 띄워 올린다.

### 3D 해부도 릴스 — 회사가 '어떻게 일했나' 를 영상으로 (2026-09-30, 올리브영 첫 편)

정보 나열이 아니라 **한 회사가 실제로 푼 문제 하나**를 끝까지 보여준다. 참고한 형식은 archcutaway(건축해부도) —
3D 모델을 잘라 속을 보여주고 자막·목소리로 설명한다. 형식만 빌렸고 그 계정의 영상·모델·문구는 쓰지 않는다.

```
원문(회사 테크블로그 한 편) → reels/<회사>_3d/storyboard.json(장면·자막·내레이션·고객화면·출처)
  → poster/templates/scene3d_<회사>.html(three.js 3D, #s01…) → python -m poster.cutaway reels/<회사>_3d
```

- **재료는 회사가 직접 쓴 글 하나.** 숫자·용어는 원문 그대로, 문장은 요약해 다시 쓴다. 원문 세부(왜 그렇게 했나,
  실패한 1차 시도, 안전장치, 검증 기간)까지 장면으로 푼다 — 요약만 하면 "무엇" 만 남고 "왜" 가 빠진다.
- **3D 는 우리가 코드로 짠다**(`poster/scene3d.py` + three.js, `poster/vendor/`). 생성 AI 를 쓰지 않으니 권리·사칭 걱정이
  없고, 3D 속 글자도 캔버스로 그려 오탈자가 없다. 트럭·신호등 같은 사물은 개념을 보이려는 비유라고 화면에 '연출' 표시.
- **구도는 계산한다.** 장면 전체 시간의 물체 위치를 여러 시점에서 모아, 화면(자막·고객 화면 자리 제외) 안에 들어오는
  거리를 투영으로 찾는다. 첫 프레임만 보면 나중에 움직이는 것이 잘린다. 가로로 긴 장면은 카메라를 옆으로 돌려
  긴 축을 화면 깊이로 보낸다(세로 화면은 가로 시야가 좁다).
- **목소리가 장면 길이를 정한다.** 내레이션(`edge-tts`, SunHi)을 먼저 만들고 장면 = 목소리 + 0.9초. 애니메이션은 5초
  기준으로 짜고 장면 길이 전체로 늘린다 — 안 늘리면 목소리는 나오는데 화면이 멈춰 있다(첫 판에서 겪었다).
  공개 게시용 음성 권리는 상업 사용이 허용된 서비스(클로바 더빙·일레븐랩스 등)로 바꾸는 것을 검토한다.
- **고객 화면(PIP)** — 오른쪽에 작은 폰을 계속 띄워, 시스템이 바뀌는 동안 고객이 무엇을 보는지(45분 늦은 혜택 →
  수 초 반영) 이어 보이게 한다. 몰입의 장치다.
- **캡션에 출처를 전부**: 원문 제목·날짜·글쓴이(필명)·주소, 숫자의 출처, 브랜드 색 출처, 연출·AI 음성 표시,
  "회사와 관계없는 개인 계정의 해설".
- 결과물(mp4·클립·프레임·음성)은 커밋하지 않는다(`design-lab/.gitignore`). 대본·캡션·코드가 원본이다.
- 인스타는 API 가 막혀 있어 웹 업로드 요청(5절)으로 직접 올린다.

## 4. 검수 — 올리기 전에 반드시

한 게시물씩 `inbox/<id>/` 를 연다. 아래 중 하나라도 걸리면 올리지 않는다.

1. **모집이 끝났나** — 원본 사이트에 다시 묻는다(`publish.openness.check`). 9/30 에 이번 주 묶음의
   포티투닷 공고가 전날 승인 뒤 마감돼 빠졌다. 올리는 날 아침에 다시 확인한다.
2. **이미 낸 공고인가** — `publish/posted.py`. 원장 `state/publish_queue.json` 과 inbox 를 본다.
3. **숫자에 기준일과 n 이 있나** — 데이터 카드는 모든 장 아래에 `모집중 개발 공고 N건 · YYYY. MM. DD 수집 기준`.
   표본이 적은 칸(외주 초급 13건·특급 12건)은 "참고만" 이라고 적는다.
4. **판이 넘치거나 잘렸나** — `series.render` 가 `넘침=True`·최소 글자 18px 미만이면 경고한다.
5. **첫 장이 4:5 인가** — 1080×1350. 올릴 때 비율을 다시 확인한다(5절).
6. 판에 채용 사이트 이름·공고 주소가 없나. 주소는 캡션에만.

## 5. 올리기

### 속도 — 새 계정은 천천히

- 1–2주차 **하루 1–2개**, 3–4주차 하루 2개(12:30·19:30), 그 뒤 하루 3개까지. 게시물 사이 **3시간 이상**.
- 몰아 올리면 스팸 판정이 난다(타이밍 패턴·캡션 유사도를 본다). 캡션과 해시태그 조합을 게시물마다 바꾼다.
- 10개 한 묶음을 만들면 **5–7일에 나눠** 올린다. 오늘 만든 10개의 순서는 6절 표.

### 방법 — 지금은 브라우저

인스타 Graph API 가 2026-09-30 현재 `API access blocked.`(code 200)다. 데몬(`publish.daemon`, 맥)은 쓸 수 없고
크롬에서 직접 올린다.

1. 크롬 창을 **최소화하지 않는다.** 탭이 가려지면(`visibilityState: hidden`) 사진은 올라가지만
   **캡션이 저장되지 않는다** — 붙여넣으면 글자 수(1010/2200)는 올라가는데 올라간 게시물은 빈 캡션이다.
   수정 창은 흐린 채(투명도 0) 멈추고 '완료' 가 요청을 보내지 않는다. 1분 넘게 기다리기·
   requestAnimationFrame 대체·visibilityState 속이기 모두 안 됐다(9/30, 올리브영·컬리가 빈 캡션으로 올라갔다).
   올리기 전에 `document.visibilityState === 'visible'` 을 확인하고, 아니면 올리지 않는다.
2. `+ → 게시물` 대화창의 **여러 장을 받는 입력칸**(`input[type=file][multiple]`, 대화창 안)에만 파일을 넣는다.
   프로필 머리의 입력칸은 **프로필 사진 변경**이다(9/30 에 실제로 프로필 사진이 바뀌었다).
3. 자르기 단계에서 `자르기 선택 → 4:5`. 기본이 1:1 이라 그냥 넘기면 판 위아래가 135px 씩 잘린다.
4. 캡션은 **붙여넣기(paste 이벤트)** 로 넣고 글자 수 표시(`413/2200`)가 올라갔는지 본다. 키 입력으로 긴 글을
   치면 편집기 상태에 안 들어가거나 창이 닫힌다.
5. 공유 뒤 게시물 페이지의 `og:description` 에 캡션 첫 줄이 들어갔는지 확인한다.

**캐러셀도 웹 업로드 요청으로 — 캡션까지 한 번에.** 사진마다 `POST /rupload_igphoto/<id>`(`is_sidecar: 1`) 로 올린 뒤
`POST /api/v1/media/configure_sidecar/`(JSON: `caption`, `children_metadata: [{upload_id}…]`, `client_sidecar_id`) 한 번.
가려진 탭에서도 캡션이 들어간다(9/30 [IT 용어]·[면접 예상 질문]·[고민 상담소]). 요청 사이에 `setTimeout` 을 넣지 않는다 —
가려진 탭에서는 타이머가 분 단위로 늦춰져 확인 호출이 45초를 넘긴다(요청은 페이지 안에서 계속 가므로 게시물 수로 확인).

**릴스는 웹 업로드 요청으로 — 창이 가려져도 된다(9/30 에 10편을 이렇게 올렸다).** 가려진 탭에서는 크롬이
`<video>` 를 아예 불러오지 않아(`readyState 0`) '새 게시물' 대화창이 영상을 받은 뒤 멈춘다. 대신 인스타 웹이
쓰는 업로드 요청을 로그인된 페이지에서 직접 보낸다(캡션까지 한 번에 들어간다).

```
1. POST /rupload_igvideo/<upload_id>_0_<난수>   본문 = mp4
   x-instagram-rupload-params: {media_type:2, upload_id, upload_media_duration_ms, 1080×1920, is_clips_video:1}
2. POST /rupload_igphoto/<upload_id>_0_<난수>   본문 = 표지 jpg(9:16 첫 장면 _reel/01.jpg), media_type:2
3. POST /api/v1/media/configure_to_clips/       upload_id, caption, clips_share_preview_to_feed=1
   → 202 "Transcode not finished yet" 이면 몇 초 뒤 3만 다시 부른다(1·2 를 다시 하면 중복 영상이 생긴다)
```

헤더는 `x-csrftoken`(쿠키) · `x-ig-app-id: 936619743392459` · `x-requested-with`. 파일은 페이지에 임시
`input[type=file]` 를 붙이고 크롬 확장의 file_upload 로 넣어 `files[0]` 로 읽는다. 가려진 탭은 타이머가
분 단위로 늦춰지므로 **대기(setTimeout)를 스크립트 안에 넣지 않는다** — 3 을 다시 부르기 전에 게시물 수
(`/devjobseeker/` 의 og:description "게시물 N개")로 이미 올라갔는지 먼저 본다. 조회 API(`web_profile_info`)는
금방 429 가 난다.

**창을 띄울 수 없을 때 — 설명은 첫 댓글로.** 윈도우 크롬은 다른 창에 완전히 덮인 창도 `hidden` 으로 본다.
그때도 사진 올리기와 **댓글은 된다**(댓글 칸은 일반 textarea 라 값 넣고 `input` 이벤트 → '게시'). 9/30 의 10개는
전부 이렇게 올렸다: 캐러셀을 캡션 없이 올리고 → 새 게시물 주소를 프로필에서 찾고 → 캡션 파일을 페이지의
임시 `input[type=file]` 로 넣어 읽은 뒤 계정 이름으로 첫 댓글을 단다. 창이 보일 때는 캡션에 넣는 게 낫다
(검색은 캡션을 본다).

### 순서

`poster.jpg`(첫 장) → `slide_01.jpg`(차례) → `slide_02…`(공고 판). 파일 이름 순서가 캐러셀 순서다.

## 6. 원장 기록 — 두 번 올리지 않게

올린 직후 원장에 `published` 로 적고 묶음 폴더를 `inbox/_manual/` 로 옮긴다. inbox 에 그대로 두면 나중에
`publish.cli push` 가 맥으로 보내 **같은 게시물이 한 번 더 나간다.**

```python
from publish import queue
queue.add_approved(bundle, image_rel, images)
queue.update(id, status="published", posted=["instagram"], results={"instagram": {"url": url, "via": "chrome-manual"}})
```
