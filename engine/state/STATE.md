# 진행 상황

엔진은 실행 사이에 기억이 없다. 다음 사이클이 이어받을 맥락을 여기에 남긴다.

## 지금 파는 중

**Stripe 진행 중 — 해외 첫 회사.** 도메인 **6개** 중 4개 완료 · 기능 5개
(`idempotent-payments`+`api-surface` 결제 API·개발자 제품, `ledger` 자금 기록·검증,
`radar` 리스크, `docdb-migrations` 데이터 인프라).
남은 도메인 2개: **결제 처리·결제수단**(자료 못 찾음) / **매출 운영**(자료 있음 — 아래 참고).
검증 경고 3건(Stripe 2 + 카카오 1).
> `데이터 인프라` 도메인을 **새로 세웠다** — DocDB 자료가 기존 다섯 도메인 어디에도 안 맞았다.
> 도메인 이름을 바꿀 때는 각 feature 의 `domain` 필드도 함께 고칠 것(사이클 059 에서 검증 오류로 잡혔다).
> **stripe.dev 블로그 본문은 JS 렌더링이라 WebFetch 로는 제목만 온다** — 브라우저 navigate →
> `get_page_text` 를 써야 한다(이번 사이클에서 확인). 앞선 세 글은 우연히 WebFetch 로 읽혔다.
> `정산·계정(Connect)` 도메인을 **`자금 기록·검증` 으로 옮겼다** — 자료가 다룬 것은 Connect 가
> 아니라 Ledger 였다. Connect 는 도메인 tech 에 `미확인` 으로 남겼다.
> **stripe.com/blog/* 는 stripe.dev/blog/* 로 301 리다이렉트된다** — WebFetch 가 리다이렉트를
> 따라가지 않으니 처음부터 stripe.dev 로 부를 것.
> **공식 문서(docs.stripe.com)를 1급 출처로 쓴다.** 회사가 스스로 약속한 계약이므로 '회사가 말한
> 것'에 해당한다. 다만 문서에는 날짜가 없어 source.date 를 `2026-08 확인` 으로 적었다.
> 영문 자료는 WebFetch 로 잘 읽힌다(medium 과 달리 403 이 없다).

**무신사 완주.** 도메인 3개 · 기능 3개(상품 이해·속성 · 개인화·추천 · 검색·랭킹).
검증 경고 0건. **사이트 전체에 남은 경고는 카카오 1건뿐이다.**
> `입점 브랜드·파트너` 도메인은 **자료에 맞춰 없앴다.** 우리가 가진 파트너 이야기(속성 입력 부담)는
> 이미 `상품 이해·속성` 안에 들어가 있고, 정산·수수료·파트너 도구는 공개 엔지니어링 자료가 없다.
> 빈 도메인을 영구히 남기는 대신 경계를 옮기고, 없는 것은 open_questions 에 적었다(당근 선례).

**완주 6개:** 토스 · 네이버 · 배민 · 당근 · 쿠팡 · 무신사. 보류 1개: 카카오. **비교 문서 8개.**

**카카오 — 두 번째 확인도 실패.** `동기화·다중 기기` 자료를 다시 찾았지만 tech.kakao.com·
if(kakao)·medium 어디에도 엔지니어링 글이 없다. 검색에서 나온 건 커뮤니티·위키의 제품 이야기뿐이고
(같은 종류 기기 동시 로그인은 아직 지원되지 않는다는 취지), cs.kakao.com 은 SPA 라 본문을 못 읽었다.
**출처 기준에 못 미치므로 아무것도 쓰지 않았다.** 세 번째 시도는 하지 않는다 — 새 발표가 나왔다는
단서가 생기기 전까지 보류로 둔다.

(완주: 토스 · 네이버 · 배민 · 당근 · 쿠팡 — 5개. 비교 문서 7개.)
> 물류센터 도메인은 채웠지만 **재고 배치 알고리즘 자체는 여전히 미확인**이다. 자료가 다룬 것은
> 그 알고리즘을 '만드는 도구'였다 — 도메인 tech 에 `미확인` 항목으로 명시해 두었다.
(직전 완주: **당근** 도메인 5 · 기능 5 · 경고 0)

## 이제 무엇을 할까 — 다음 사이클의 선택지

1. **새 비교 문서 (재료가 이미 있고 가장 값싸다).** 후보 둘:
   - **추천은 무엇을 섞는가** — 무신사(개인화 옆에 대중적 추천을 둔다) · 당근 `feed-platform`
     (Feed Mixer 가 미성장 서비스 콘텐츠를 섞는다) · 네이버 `smart-block`(생성과 랭킹을 분리해
     인기 주제가 새 주제를 밀어내는 되먹임을 끊는다). **세 회사가 '개인화만 하면 안 된다'는 같은
     결론에 서로 다른 방식으로 도달한다** — 지금 가장 좋은 축이다.
   - **카탈로그의 세 가지 상태** — 쿠팡(정리돼 있다) · 무신사(있는데 말이 통일 안 됐다) ·
     당근(아예 없고 팔리면 사라진다).
2. **해외 회사로 넘어간다.** QUEUE 의 해외 목록(Instagram · Netflix · YouTube · Uber · Stripe ·
   Discord · Shopify)은 전부 영문 기술블로그가 두껍다. 새 나라·새 카테고리가 들어오면 비교의
   폭도 넓어진다. 첫 회사로는 **Stripe(결제 — 토스 `payment-approval` 과 바로 대조된다)** 나
   **Uber(실시간 매칭 — 카카오 택시·배민 배차와 3사 비교가 된다)** 가 기존 문서와 가장 잘 붙는다.
3. 카카오는 건드리지 않는다(두 번 확인해 두 번 다 자료 없음).
