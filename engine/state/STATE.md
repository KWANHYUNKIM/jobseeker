## 지금 파는 중

*(덮어쓴다. 이어붙이지 않는다.)*

**아무 회사도 파는 중이 아니다. GitHub 이 완주하면서 22곳이 전부 done 이 됐다.**
다음 사이클은 `--gaps` 가 가리키는 대로 **큐 맨 위(LY Corporation / LINE)를 새로 연다.**

> **LY 를 열 때 알아야 할 것** — 1차 자료는 `techblog.lycorp.co.jp/en` 이고 본문은 확인됐다.
> ⚠️ **기사 URL 을 추측하지 말 것.** 목록 페이지에서 실제 주소를 딸 것(한 번 404 를 맞았다).
> 첫 기능 후보는 **Kafka E2EE** — 초당 100만 메시지 토픽에 종단간 암호화를 무중단으로 얹은
> 기록이다(레코드 단위 대 배치 단위, DEK-KEK, 공유 KEK 의 대가까지). **일본 회사가 0곳**이라
> index.json 이 JP 를 정의해 두고 비어 있는 것도 이 회사를 먼저 여는 이유다.

> **GitHub 에서 나온 것 — 네 도메인에 걸친 반복 패턴을 business_model 에 적었다.**
> ① 쪼개는 기준을 데이터의 성질에서 가져온다(블롭 ID · 함께 쓰이는 테이블 · 저장소 단위)
> ② 옮기기 전에 선부터 긋는다(schema-domains.yml + 린터, 체크섬)
> ③ 하나에 전부 걸지 않는다(Vitess + 자체 write-cutover, 8.0→5.7 역방향 복제)
> ④ 물리 한계 앞에서는 병렬화로 물러선다(대륙 간 왕복을 겹쳐 돌리기, 캐시를 이미지로 옮기기)

> **새 축 — '일회용인데 빨라야 한다.'** 격리와 준비 시간이 같은 손잡이의 양 끝이다. 캐시를
> 넣으면 낡고, 낡으면 따라잡는 비용이 캐시가 아낀 시간을 갉아먹는다. GitHub 의 답은
> **캐시를 잡이 아니라 이미지에 넣고 하루 여러 번 다시 만드는 것**(50분 → 12분)인데,
> 그 비용이 사라진 게 아니라 이미지 파이프라인으로 옮겨 갔을 뿐이다. Dropbox 'SSD 캐시를
> 뗀다'·GitHub '케이스 폴딩'과 같은 결이라 비교 문서에 함께 쓸 수 있다.

> **한 도메인당 최소 두 글 규칙이 네 사이클 연속 값을 했다.** GitHub 데이터 계층은 2021 +
> 2023 을 겹쳐야 규모가 갱신되고(초당 120만 → 550만 쿼리), Spokes 는 2016 두 글 + 2017 을
> 겹쳐야 '복제본을 가까이 모아 둬야 했던 초기 제약'이 드러난다.

> **작업 메모:** `github.blog` 는 WebFetch 로 잘 읽힌다. 다만 **최근 글이 AI 제품 발표
> 쪽으로 기울어** 인프라 글은 2016~2023년 것을 찾아야 한다.

### 되풀이되는 설계 축

여러 회사에서 같은 모양이 반복해서 나온 것들. 비교 문서의 씨앗이자, 새 회사를 팔 때
"여기도 같은 문제가 있나"를 먼저 물어볼 목록이다.

  Shopify 판매 단위당 1행 / 토스 계좌 락 / Discord 요청 병합 / Stripe 멱등 키.
- **몰리는 것을 한 곳에서 합친다** — Discord 요청 병합·Manifold·길드당 음성 서버 1대.
- **터진 뒤 끊는 대신 들어가기 전에 센다** — Discord Semaphore·침묵 억제.
- **격리의 단위가 곧 전환의 단위** — Shopify pod 이동·리전 페일오버·pod 단위 점진 전환.
- **분포에 맞춘 설계는 분포 밖에서 정확히 실패한다** — Slack 여러 샤드 순회가 보통
