## 지금 파는 중

*(덮어쓴다. 이어붙이지 않는다.)*

**Canva — 26번째 회사, 호주 첫 회사.** 사이클 158 에서 열었다. 프로파일 + 도메인 2개 +
기능 1개(`session-revocations`).

> **⚠️ 엔진 코드를 한 줄 고쳐야 했다** — `engine/validate.py` 의 `COUNTRIES` 에 **`AU` 를 추가**했다.
> index.json 의 `countries` 맵에도 `AU: 호주` 를 넣었다. **새 나라를 여는 회사는 이 두 곳을 함께
> 고쳐야 한다** — 다음에 또 겪을 일이니 기록해 둔다.

> **다음 기능 후보 — `인쇄 주문 라우팅`, 본문 확인 완료.** 이 엔진에 없던 축이다: **소프트웨어가
> 끝나는 자리에서 시작하는 물리 공급망.** 관계형 DB 를 진실의 원천으로 두고 그래프를 만들어
> **목적지 지역으로 샤딩해 Redis** 에 싣는다. 순회는 **최소비용유량 변형(successive shortest
> path, O(VE))** 에 **후회(regret)** 를 얹은 것. **다익스트라를 버린 이유가 명시돼 있다 —
> 순회와 비용 판단이 묶여 있어서, 둘을 분리해 독립 최적화하고 A/B 로 시험하고 싶었다.**
> 수치: 조회 대부분 6ms(큰 샤드 20ms), 피크 p99 **50ms**, p50 30ms 이하, 가용성 **99.999%**.
> ⚠️ **두 번째 글을 아직 못 찾았다** — 없으면 `snowpipe-streaming` 등으로 다른 도메인을 열거나
> 이 도메인을 한 글로 채우되 그 사실을 남긴다.

> **session-revocations 에서 나온 축 — '문제를 없앤 게 아니라 비례하는 대상을 바꿨다.'**
> 배포 때 수백 파드가 DB 를 때리는 스탬피드의 부하는 **파드 수와 시간 창 크기**에 비례했다.
> S3 로 옮긴 뒤에는 **쓰기 처리량과 트래픽**에 비례한다. 그리고 확장에 대한 태도도 눈에 띈다 —
> 읽고-고쳐-다시 쓰는 구조라 수평 확장이 안 되는데, **확장 가능하게 만드는 대신 배치로 묶어
> '확장할 필요가 없을 만큼' 빠르게** 만들었다(초당 2,000건, "예상 가능한 요구를 넘어선다").

> **🔗 방금 쓴 비교 문서 `잘못된 자를 어떻게 알아채는가` 에 붙을 재료가 하나 더 나왔다.**
> Canva 의 API 게이트웨이 장애에서 **카나리아가 아무 오류도 못 봤는데, 이유가 "요청이 실패한
> 게 아니라 완료되지 않아서"** 였다 — 오류율은 정상으로 보였다. 그래서 **페이지 로드 완료
> 이벤트를 카나리아 지표로 추가**하기로 했다. 이건 그 문서의 축과 정확히 같다. **아직 문서에
> 넣지 않았다** — 회사를 완주한 뒤 문서를 갱신할 때 넣을 것.

> **비교 문서 후보 (③이 여전히 가장 재료가 많다)** — ③ 양 끝 대신 축을 바꾸는 수(LY 공유 KEK ·
> GitHub 일회용 러너 · Dropbox SSD 캐시 · Spotify RAP). ② 틀려도 되는 일 vs 안 되는 일.
> ④ 작은 파일. ⑤ 시스템 두 벌(LY · Spotify 의 Podz 인수). **⑧ 새로 보임 — '외부에 맡길 것인가
> 직접 운영할 것인가'**(Canva 가 Redis 를 "클러스터를 우리가 운영해야 한다"며 버리고 S3 로 간 것 ·
> Spotify 가 K8s 대신 Dataflow 를 고른 것 · ByteDance 가 자체 저장 엔진을 만든 것 — **정반대 방향**).

  Shopify 판매 단위당 1행 / 토스 계좌 락 / Discord 요청 병합 / Stripe 멱등 키.
