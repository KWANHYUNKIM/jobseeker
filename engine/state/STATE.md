## 지금 파는 중

*(덮어쓴다. 이어붙이지 않는다.)*

**ByteDance — 도메인 4개 중 2개에 기능이 있다**(`monolith` 온라인 추천 학습, `megascale` 만 대 학습).
사이클 150 에서 **계획을 바꿔야 했다.**

> **🚫 재시도 안 함 — VLDB PDF 는 이 환경에서 읽을 수 없다.** LavaStore(`vldb.org/pvldb/vol17/p3799-jiao.pdf`)를
> **두 번** 시도했다. 첫 응답은 그럴듯한 요약을 냈지만 **수치가 전부 '30-40%', '20-35%' 같은
> 범위**였고, 같은 파일을 다시 부르니 **"바이너리 PDF 스트림이라 읽을 수 없다"**고 답했다 —
> **첫 요약은 지어낸 것이다.** 로컬에도 poppler·pypdf·pdftotext가 전혀 없어 Read 도 실패한다.
> **그래서 그 요약을 한 줄도 쓰지 않았다.** ByteGraph·ByteHTAP 도 같은 형식이라 같은 처지다.
> **교훈: WebFetch 요약의 수치가 전부 '범위'로 나오면 의심하고 같은 URL 을 한 번 더 불러 본다.**

> **✅ 되는 것:** `ar5iv.labs.arxiv.org/html/<id>` 는 **arXiv 논문 전문**을 실험 표·인용문까지 그대로
> 준다. 이번에 MegaScale(2402.15627)을 그렇게 정독했다. `arxiv.org/abs/<id>` 는 초록만 준다.

> **다음 사이클의 판단** — ① **arXiv 에 있는 ByteDance 논문을 더 찾아** 새 도메인을 연다
> (검색어: `arxiv ByteDance` + 추천/서빙/스케줄러/네트워크). ② 더 없으면 **ByteDance 를 done 으로
> 닫고**, 기능 없이 남는 두 도메인은 **읽을 수 없어서 못 팠다**는 사실을 open_questions 에 남긴다
> (이미 적어 두었다). **자료가 있는데 안 판 것과 읽을 수 없어서 못 판 것은 다르다.**

> **MegaScale 에서 나온 것 — 이 엔진에 처음인 결.** 논문의 절반이 최적화이고 절반이 **관측**이다.
> 저자들이 놀란 대목이 값지다 — **같은 설정으로 돌려도 실행마다 효율이 달랐고**, 원인인 0.5%의
> 느린 기계는 **단일 GPU GEMM 마이크로벤치마크로는 안 보였다.** 답은 더 나은 벤치마크가 아니라
> **벤치마크를 버리고 실제 부하를 관측 대상으로 삼는 것**이었다. MFU 가 시간이 갈수록 떨어지던
> 범인은 **불규칙한 가비지 컬렉션과 일부 PyTorch 연산**이었다.

> **한 회사 안에서 정반대인 두 학습을 갖게 됐다** — Monolith 는 **작은 갱신이 끝없이 흐르는**
> 온라인 학습이고 MegaScale 은 **거대한 한 판을 수 주 버티는** 배치 학습이다. 잃는 것을 세는
> 단위도 다르다(사용자 15,000명의 하루치 vs 유효 학습 시간 90%). 두 논문은 서로를 인용하지 않는다.

> **비교 문서 후보 다섯 (변동 없음, ①이 가장 유망)** — ① 완벽한 탐지를 포기하고 확률로 좁히는 자리
> (LY 어테스테이션 · Discord 안전 · 유튜브 Content ID · 토스 이상거래). ② 틀려도 되는 일 vs 틀리면
> 안 되는 일(ByteDance 추천 ↔ 토스·스트라이프 원장). ③ 양 끝 대신 축을 바꾸는 수. ④ 작은 파일 문제.
> ⑤ 합병으로 시스템이 두 벌이 된 회사.

### 되풀이되는 설계 축

여러 회사에서 같은 모양이 반복해서 나온 것들. 비교 문서의 씨앗이자, 새 회사를 팔 때
"여기도 같은 문제가 있나"를 먼저 물어볼 목록이다.

- **충돌을 해결하는가, 충돌이 안 생기게 만드는가** — Figma 속성 단위 LWW·분수 인덱싱 /
  Shopify 판매 단위당 1행 / 토스 계좌 락 / Discord 요청 병합 / Stripe 멱등 키.
- **몰리는 것을 한 곳에서 합친다** — Discord 요청 병합·Manifold·길드당 음성 서버 1대.
- **터진 뒤 끊는 대신 들어가기 전에 센다** — Discord Semaphore·침묵 억제.
- **격리의 단위가 곧 전환의 단위** — Shopify pod 이동·리전 페일오버·pod 단위 점진 전환.
- **분포에 맞춘 설계는 분포 밖에서 정확히 실패한다** — Slack 여러 샤드 순회가 보통
  사용자에겐 잘 돌고 수백 워크스페이스에선 무너져 50개로 자른 것 / Discord 대형 길드.
- **미리 한계를 찾아 두고 되돌릴 길을 열어 둔다** — Shopify 스케일 테스트·섀도 모드·
