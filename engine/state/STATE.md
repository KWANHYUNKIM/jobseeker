# 진행 상황

엔진은 실행 사이에 기억이 없다. **다음 실행이 이어받을 맥락만** 여기에 남긴다.

> 이 파일은 매 사이클 통째로 읽힌다. 그래서 **자란다면 잘못 쓰고 있는 것이다.**
> 사이클 기록은 `LOG.md` 로 간다(엔진은 그 파일을 읽지 않는다). 여기 남기는 것은
> "다음 실행이 모르면 헛수고할 것"뿐이다. 각 절의 규칙은 절마다 적어 뒀다.

## 지금 파는 중

*(덮어쓴다. 이어붙이지 않는다.)*

**GitHub — 진행 중. 22번째 회사다.** 도메인 4개 중 **2개 완료** — 코드 검색(`blackbird`),
Git 저장·복제(`spokes-replication`). 남은 것: **데이터 계층 · CI 실행.**

> **이 회사의 축 — 남의 코드를 맡고, 실행하고, 검색해 준다. 셋 다 규모의 성질이 다르다.**
> 저장은 3배 복제(Spokes), 실행은 순간 폭증(Actions), 검색은 중복 제거(블롭 ID 샤딩).
> 원가가 고객 수가 아니라 **고객이 밀어 넣는 양**에 비례한다.

> **⚠️ 범위 주의를 business_model 맨 앞에 달았다.** Microsoft 산하라 **GitHub 단독 재무가
> 공시되지 않는다.** 회사가 밝힌 것은 유료 Copilot 좌석 470만(2026-01-28)뿐이고,
> ARR 30억 달러 초과는 **보도이지 발표가 아니다** — 수익원 셋을 전부 `inferred` 로 뒀다.

> **한 도메인당 최소 두 글 규칙이 또 값을 했다.** Spokes 는 2016(DGit) → 2016(회복력) →
> 2017(대륙 확장) 세 글을 겹쳐야 이야기가 완성된다. 2016년 글만 읽으면 **복제본을 가까이
> 모아 둬야 했던 초기 제약**과 그걸 어떻게 풀었는지가 통째로 빠진다.

> **새 축 — '왕복 수를 못 줄이면 겹친다.'** 3단계 커밋 네 왕복 × 60~80ms 는 빛의 속도가
> 정한 하한이라 알고리즘으로 못 넘는다. 그래서 순서를 겹쳤다(한쪽이 락을 잡는 동안 다른
> 쪽은 체크섬 계산). **물리 한계 앞에서 병렬화로 물러선 사례**로 비교 문서에 쓸 값이 있다.

> **작업 메모:** `github.blog` 는 WebFetch 로 잘 읽힌다. 다만 **최근 글이 AI 제품 발표
> 쪽으로 기울어** 인프라 글은 2016~2023년 것을 찾아야 한다.

**큐 3/3 — 충분.** 다음 대기는 LY(LINE) → ByteDance → Spotify.

### 되풀이되는 설계 축

여러 회사에서 같은 모양이 반복해서 나온 것들. 비교 문서의 씨앗이자, 새 회사를 팔 때
"여기도 같은 문제가 있나"를 먼저 물어볼 목록이다.

- **충돌을 해결하는가, 충돌이 안 생기게 만드는가** — Figma 속성 단위 LWW·분수 인덱싱 /
  Shopify 판매 단위당 1행 / 토스 계좌 락 / Discord 요청 병합 / Stripe 멱등 키.
- **몰리는 것을 한 곳에서 합친다** — Discord 요청 병합·Manifold·길드당 음성 서버 1대.
- **터진 뒤 끊는 대신 들어가기 전에 센다** — Discord Semaphore·침묵 억제.
- **격리의 단위가 곧 전환의 단위** — Shopify pod 이동·리전 페일오버·pod 단위 점진 전환.
- **분포에 맞춘 설계는 분포 밖에서 정확히 실패한다** — Slack 여러 샤드 순회가 보통
  사용자에겐 잘 돌고 수백 워크스페이스에선 무너져 50개로 자른 것 / Discord 대형 길드.
- **미리 한계를 찾아 두고 되돌릴 길을 열어 둔다** — Shopify 스케일 테스트·섀도 모드·
  Verifier·성수기 변경 동결 / 토스 카나리 자동 롤백.
