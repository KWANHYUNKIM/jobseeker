## 지금 파는 중

**카카오 — 기능 6개.** 도메인 7개 중 6개 완료. 남은 것은 **동기화·다중 기기** 하나인데
**자료가 없다.** tech.kakao.com 의 Messaging 태그를 브라우저로 확인한 결과 카리브 3편뿐이고
카카오톡의 다중 기기 동기화·읽음 확정을 다룬 글은 없었다(028에서 확인 — 다시 찾지 말 것).
검증 경고 1건이 그 도메인의 tech 다. **완주 판정 보류.**

**자료 접근 — 앞 사이클 기록을 정정한다.**
- ⚠️ `tech.kakao.com` 은 **WebFetch 로는 껍데기만 온다**(본문이 JS 렌더). 022 에서 'fetch
  가능'이라고 적은 것은 목록 페이지만 보고 내린 성급한 판단이었다.
- ✅ **브라우저(claude-in-chrome)로 열면 본문을 읽을 수 있다.** 023 은 그렇게 원문을 읽었다.
  네이버 D2 도 같은 방법이 통할지 모른다 — 다음에 시도해 볼 것.
- ✅ `kakaocorp.com` IR·뉴스룸은 WebFetch 로 읽힌다.

## 다음 사이클 메모

- 비교 문서 3장(`webtoon-distribution`, `payments`, `ad-surface`). 셋 다 새 조사 없이
  기존 confirmed 사실만으로 썼다. **비교는 조사가 아니라 재배열이라는 것**이 확인됐다.
- `ad-surface` 에서 나온 축: **광고가 그 화면에서 어떤 지위인가.** 네이버 검색 결과에서
  광고는 결과와 같은 종류라 경쟁이 '순서'에서 일어나고, 카카오 대화 목록에서 광고는
  이질적인 손님이라 문제가 '들어올 수 있는가'가 된다. 지면을 가진 다른 회사를 볼 때
  먼저 물어볼 질문이다.
- 남은 비교 문서 후보:
  - **인증/신원** — 토스 `request-passport`(요청이 진짜인가) + `identity-certificate`
    (이 사람이 동의했는가) 대 카카오 `identity-trust`(이 사람이 사칭인가). 같은 '신원'인데
    묻는 것이 셋 다 다르다.
  - **실시간 전달** — 토스의 Kafka 결과 발행 대 카카오 카리브의 성능 정의.
- 다음은 **배달의민족**(QUEUE 맨 위). 카카오 `taxi-dispatch` 와 정면 대조군이 된다 —
  둘 다 현실의 이동을 다루지만 배민은 '음식이 식는다'는 시간 제약이 하나 더 있다.
  프로파일부터 시작하고, 도메인은 앞 세 회사의 틀을 복사하지 말 것.
