## 다음 사이클 메모

- 배차에서 나온 관점: **이 도메인은 '정확한가'만으로 부족하고 '설명할 수 있는가'까지가
  요구 사항이다.** 수락 확률 예측은 거절 낭비를 줄이지만, 많이 수락한 기사가 더 받는
  되먹임을 만든다 — 효율 장치가 그대로 공정성 문제의 씨앗이 된다. 그래서 원래 공개하지
  않는 배차 로직을 외부 검증까지 붙여 공개했다. **사람의 생계에 직접 닿는 판단을 하는
  시스템에는 설명 가능성이 기능 요구사항으로 들어온다** — 다른 회사에도 물어볼 각도다.
- 도메인 간 연결이 하나 확인됐다: 배차 조건에 '이 기사 만나지 않기' 지정 횟수가 들어간다.
  관계·프레즌스 도메인의 개념이 모빌리티의 실제 매칭을 바꾼다(confirmed).
- 남은 둘:
  1. **관계·프레즌스** — 위 연결이 이미 실마리다. 오픈채팅 익명성·신고·차단으로 확장.
  2. **동기화·다중 기기** — 여전히 자료를 못 찾았다. tech.kakao.com 을 브라우저로 열어
     'Backend'·'Messaging' 태그 목록을 훑어볼 것. 그래도 없으면 도메인 설명만 남기고
     완주 판정을 보류한다(네이버 '지면 구성' 때처럼 억지로 채우지 않는다).
- 모빌리티·페이는 모빌리티 축만 채웠다. 페이(결제·정산)는 open_questions 에 남겼다.
