# 취업 브리핑 사이클

**한 번 호출 = 한 사이클 = 한 대상 = 한 커밋.** 두 개를 욕심내지 않는다.

## 이 스킬이 있는 이유

엔진의 규칙은 전부 `guide-engine/` 안의 문서에 있다. 이 스킬은 그 문서를 **어떤 순서로
읽고 무엇으로 시작해 무엇으로 끝내는지**만 정한다. 규칙 자체를 여기 복사하지 않는다 —
복사본은 반드시 원본과 어긋나고, 어긋난 순간 어느 쪽이 맞는지 아무도 모르게 된다.

> 역설계 엔진(`/reveng`)과 **다른 엔진이다.** 큐도 상태도 산출물도 따로다.
> 저기는 "이 회사가 기술적으로 어떻게 만들어졌나", 여기는 "내가 저기 들어가려면 뭘 하나".

## 절차

### 1. 읽는다 (순서 고정)

레포 루트에서:

1. `guide-engine/PROMPT.md` — 무엇을 쓸지. 사이클 절차의 단일 소스.
2. `guide-engine/state/STATE.md` — 지난 사이클이 남긴 맥락.
3. `guide-engine/schema.json` — 형식. **필드를 지어내지 않는다.**

### 2. 대상을 고른다

```bash
python3 guide-engine/validate.py --gaps
```

출력이 사다리 순서 그대로 **이번 대상 하나**를 지목한다. 규칙의 원본은 PROMPT.md 2단계다.
요약하면: 오류 → 진행 중인 회사의 안 채운 공고 → QUEUE → 보강 → 재방문 → 후보 조사.

**`--gaps` 를 건너뛰고 감으로 고르지 않는다.** 사람이 기억으로 고르면 쉬운 것만 반복한다.

### 3. 쓴다

공고 본문은 웹에서 다시 긁지 않는다 — `jd-viewer/public/all_jobs_enriched.json` 에
`full_jd` 까지 통째로 있다. `python3` 로 URL 을 찍어 읽는다(60MB 라 통째로 cat 하지 않는다):

```bash
python3 -c "
import json,sys
url=sys.argv[1]
for j in json.load(open('jd-viewer/public/all_jobs_enriched.json')):
    if j['url']==url: print(json.dumps(j,ensure_ascii=False,indent=1)); break
" "<공고 URL>"
```

- **확장**(새 공고) — PROMPT.md 4단계. `verdict` → `study[]` → `edge[]` → `interview`.
- **신규**(새 회사) — PROMPT.md 3단계를 먼저. 회사 골격을 쓰고 커밋한 뒤 공고로 간다.
- **보강** — 비어 있던 칸만 채운다. `slug`·`postings[].url` 은 건드리지 않는다.

회사 조사(사업·연봉·인물)에는 WebSearch·WebFetch 를 쓴다. 세 가지 선을 지킨다.

- **연봉** — PROMPT.md 2°단계. 밴드로, `basis` 를 달아서. 근거 없으면 통째로 비운다.
- **사람** — PROMPT.md 2″단계. `public_work` 링크 없는 사람은 넣지 않는다.
  **성격·평판·소문은 출처가 있어도 쓰지 않는다.** 대부분의 회사는 빈 배열이고 그게 정상이다.
- **`quote`** — 공고 원문 그대로. 다듬으면 뷰어 하이라이트가 끊긴다.

**못 찾은 것은 비워 둔다.** 그럴듯하게 채운 한 문장이 이 데이터 전체를 못 믿게 만든다.

### 4. 검증한다 — 실패하면 커밋하지 않는다

```bash
python3 guide-engine/validate.py
```

오류(✗)가 하나라도 있으면 고칠 때까지 커밋하지 않는다. 특히 `quote 가 공고 원문에 없다`는
화면에서 조용히 사라지는 실패라, 여기서 안 잡으면 아무도 못 알아챈다.

### 5. STATE.md 를 갱신한다

- `## 지금 쓰는 중` — **덮어쓴다.** 이어붙이지 않는다.
- `## 배운 것` — 다음 사이클이 알아야 할 것만.
- `## 재시도 안 함` — 두 번 찾아 두 번 다 없었던 것.

### 6. 커밋한다

```
feat(guide): <회사> <공고>            # 확장
feat(guide): <회사> 회사 골격          # 신규 첫 사이클
fix(guide): <회사> <무엇을 고쳤나>      # 보수
docs(guide): 대기열 보충               # 후보 조사
```

데이터와 엔진 문서만. **코드 변경은 섞지 않는다.**

> `git push` 는 하지 않는다. 사용자가 명시적으로 "푸시해"라고 할 때만 한다 (CLAUDE.md).

## 아무것도 하지 않아야 하는 때

`--gaps` 가 후보 조사만 내놓는데 걸러 보니 쓸 회사가 없으면 **없는 일을 만들지 않는다.**
그 사실만 STATE.md 에 적고 끝낸다.

## 루프로 돌 때

`/loop <간격> /hireguide` 로 반복 실행된다. 매 실행은 앞 실행의 기억이 없으므로 위 절차를
매번 처음부터 밟는다. 사이클 중간에 끊겨도 STATE.md 와 커밋 이력만 보면 다음 실행이
이어받을 수 있어야 한다 — 그것이 "한 사이클 = 한 커밋" 규칙의 이유다.
