# 기술도서 엔진 — 한 사이클 절차

`/wiki` 서가에 **데이터·AI 기술도서**를 한 권씩 쓴다. 차례의 뼈대는 인프런 강의의 공개 커리큘럼에서 빌리고,
본문·예제·그림은 우리가 직접 쓴다. 형식과 검사기는 기존 책과 같다 — `jd-viewer/public/book/README.md` 를
먼저 읽는다(블록 종류, ASCII 그림 규칙, `book_check.py`, 커밋 규칙).

한 사이클 = **2~3절 = 한 커밋.** 장을 가로지르지 않는다.

## 0. 무엇을 할지 정하기

1. `jd-viewer/public/book/index.json` 에 `track: "datasci"` 이고 `status: "writing"` 인 책이 있으면 → **2. 절 쓰기**.
2. 없으면 → **1. 새 책 열기**. `book-engine/state/QUEUE.md` 의 첫 `- [ ]` 강의가 대상이다.
   대기열이 비었으면 `python book-engine/curriculum.py queue` 로 채운다.

## 1. 새 책 열기 (그 사이클은 차례 + 1장 첫 절까지)

1. `python book-engine/curriculum.py show <강의 주소>` — 섹션·수업 제목을 받는다(`state/curricula/<id>.json`).
   **받는 것은 차례뿐이다.** 수업 영상·본문(`/course/lecture`)·내부 API 는 robots 가 막고, 강사의 저작물이다.
2. 차례를 우리 책의 장·절로 다시 짠다. 섹션 하나 = 장 하나가 기본이지만 묶거나 나눠도 된다.
   **1장은 언제나 "이게 뭐고 왜 필요한가" 를 초등학생에게 설명하는 장이다** — 강의 차례에 없어도 앞에 둔다.
3. `jd-viewer/public/book/<bookId>/toc.json` 을 통째로 쓴다 — 절마다 제목·`summary`·`minutes`.
   `source` 에 강의 제목·주소·강사와 "차례만 빌렸고 본문·예제·그림은 직접 쓴 것" 이라는 `note`.
4. `index.json` 에 책을 올린다 — `track: "datasci"`, `status: "writing"`, `blurb` 에 **이 책의 절이 끝나는 '눈으로
   확인할 것'** 을 적는다(예: "직접 돌린 코드가 낸 표와 차트").
5. `QUEUE.md` 의 그 줄을 `- [x]` 로 바꾼다.

## 2. 절 쓰기 — **쉽게 먼저, 깊게 나중**

`python3 jd-viewer/scripts/book_check.py --check` 출력에서 `✓` 가 없는 첫 장의 첫 `todo` 절부터.

### 절 하나의 순서 (이 순서를 바꾸지 않는다)

| 차례 | 블록 | 무엇 |
|---|---|---|
| ① | `callout` tone `note`, 제목 "한 줄로" | 초등학생도 알아듣는 한 문장. 전문 용어 금지 |
| ② | `prose` | **일상 비유**로 설명한다 — 도서관·택배·요리·반 친구 키 재기처럼 몸으로 아는 것. 문장은 짧게 |
| ③ | `image` | 그 비유를 **그림으로**. 글 없이 그림만 봐도 뜻이 통해야 한다 |
| ④ | `steps` 또는 `code` + `sql`(lang `text`) | 손으로 해 보기 — 아주 작은 예제와 **실제로 돌린 출력** |
| ⑤ | `image` | 그 출력을 그림으로(차트·표를 그림으로 그린 것) |
| ⑥ | `heading` "조금 더 깊게" + `prose`/`terms` | 이제 전문 용어. **①~⑤의 비유와 하나씩 짝지어** 소개한다("아까 도서관 사서가 = 인덱스") |
| ⑦ | `callout` tone `trap`·`interview`·`tip` | 실무에서 막히는 곳, 면접 질문 |
| ⑧ | 마지막 블록 `sql`(lang 은 `text`·`python` 등) | 이 절이 끝나는 '눈으로 확인할 것' — 직접 돌린 결과 |
| 끝 | `recap` · `drills` · `quiz` · `sources` | `sources` 에 아래 '더 볼 자료' |

**천천히.** 한 절에 새 개념은 하나다. 두 개가 필요하면 절을 나눈다(차례를 고쳐도 된다).
첫 장들은 수식을 쓰지 않는다. 수식이 꼭 필요해지는 절에서는 숫자를 넣은 예를 먼저 보이고 기호는 뒤에 쓴다.

### 그림 — 절마다 **최소 3장**

- 파일은 `jd-viewer/public/book/<bookId>/img/<pageId>-<n>.svg|png`, 본문에서는 `image` 블록
  (`src: "/book/<bookId>/img/…"`, `alt` 필수, 한 장 600KB 이하 — 검사기가 본다).
- **직접 그린다.** 개념 그림은 손으로 쓴 SVG(상자·화살표·사람·물건을 단순한 도형으로, 글자는 크게,
  색은 3~4개). 차트는 ④에서 실제로 돌린 코드가 matplotlib 으로 저장한 것 — 지어낸 숫자로 그리지 않는다.
- 남의 그림은 **자유 이용 허락(CC0·CC BY 등)이 확인된 것만**, `credit` 에 출처·저작자·허락을 적는다.
  허락을 확인 못 하면 쓰지 않고 직접 그린다.
- ASCII 그림(`figure`)은 그림을 대신하지 않는다 — 구조를 보여 줄 때만 보조로.

### 코드는 실제로 돌린다

- 예제는 `book-engine/work/<bookId>/` 에 파일로 쓰고 `python book-engine/run.py <파일>` 로 돌린다(엔진 전용 가상환경을
  알아서 만든다 — pandas·numpy·matplotlib·scikit-learn. 더 필요하면 `python book-engine/run.py --install <패키지>`).
  `work/` 는 커밋하지 않는다. 한글이 들어간 차트는 글꼴이 없으면 깨지니 축·제목은 영어로 쓰고 한글 설명은 캡션에 둔다. 예제 데이터는 직접 만든 작은 표이거나 공개 데이터(사이킷런 내장·공공데이터·
  캐글의 공개 라이선스 데이터)다.
- **지어낸 출력을 싣지 않는다.** 못 돌렸으면 그 절은 `todo` 로 두고 끝낸다(README 의 규칙과 같다).

### 더 볼 자료 (`sources`) — 유튜브·블로그·커뮤니티·외국 자료

웹 검색으로 그 절의 주제를 잘 설명한 자료를 3~6개 찾아 **제목·주소·무엇을 볼 수 있는지 한 줄**로 단다.
국내·외국 둘 다. 공식 문서를 하나는 꼭 넣는다.

- **유튜브**: 링크와 제목만. 영상·음성·자막을 내려받거나 받아 적지 않는다(약관·robots).
  무엇을 다루는지는 제목·설명란에서 읽은 것만 쓴다.
- **블로그·커뮤니티**: 내용을 옮기지 않는다 — 우리 말로 한 줄 요약 + 링크. 인용은 한 문장 이하.
  robots 가 막은 곳·AI 수집을 금지한 곳(Reddit·Medium·brunch 등)은 열지 않는다.
- 본문에 자료의 생각을 빌렸으면 그 자리에도 출처를 단다.

## 3. 검사와 기록

1. `python3 jd-viewer/scripts/book_check.py` — 문제가 하나라도 남으면 커밋하지 않는다.
2. `book-engine/state/LOG.md` 맨 위에 한 단락: 날짜, 책·절, 그림 수, 돌린 코드, 찾은 자료.
3. 커밋(README 의 형식): `docs(book): <책 약칭> <n>장 — <그 절들이 다루는 것>`.
   `git add` 는 이 사이클이 만든 파일만 — `jd-viewer/public/book/<bookId>/`, `index.json`,
   `book-engine/state/`. `git add -A` 금지. **푸시하지 않는다.**
4. 무엇을 썼는지 한두 줄로 보고한다.

## 하지 않는 것

- 인프런 수업 내용(영상·본문·자막)을 받거나 옮기기. 차례(섹션·수업 제목)만 쓴다.
- 유튜브 영상·음성 내려받기, 자막 긁기.
- 뷰어 코드·검사기·이 문서 고치기 — 형식이 모자라면 `book-engine/state/REQUESTS.md` 에 한 줄 남기고 넘어간다.
